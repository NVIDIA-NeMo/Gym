# SWE-Together Task Limitations

This inventory describes missing tools, inaccessible inputs and validation limits recorded in SWE-Together tasks,
and compares the official published model scores on those tasks with tasks having no recorded limitation.
It covers all 109 tasks: **78 with a recorded limitation and 31 with none recorded**. A recorded limitation includes
recoverable setup friction and unavailable optional checks; it does not mean the task is impossible or that its score is invalid.

The inventory was fixed before inspecting the official scores. It comes from a review of command/output evidence
from two Gym rollouts per task, with deeper inspection of selected traces, checked against the reference recipes.
The table records that audit's observations and interpretation; it does not assert that each official model encountered
every listed problem. Original rollout transcripts are not included in this documentation; the committed inventory
preserves the classification and reference links; numeric comparisons use the official per-task results retrieved on 27 October 2026.

Reference source: [SWE-Together `891d19eb`](https://github.com/Togetherbench/SWE-Together/blob/891d19eb4b3a64a47c3d49bbd066a311e0133254), the revision pinned by Gym at the time of this review.
Official results: [per-task metrics](https://togetherbench.com/metrics.js), retrieved 27 October 2026,
with [task metadata](https://togetherbench.com/tasks.js), [leaderboard](https://togetherbench.com/) and
[paper](https://arxiv.org/abs/2606.29957) as context. This is a dated description, not a claim about future images or results.

## What the environment permits

The [reference egress policy](https://github.com/Togetherbench/SWE-Together/blob/891d19eb4b3a64a47c3d49bbd066a311e0133254/src/egress_policy.py) allows named-package downloads from npm, PyPI,
crates.io and selected distribution repositories, but blocks GitHub, Hugging Face, Go module proxies, registry search
and downloads of the task's own published packages. A package installer still needs a writable destination and
proxy-compatible networking. `allow_internet=true` in a task definition does not mean unrestricted access.

Privileges vary. Some images run as `agent` with passwordless `sudo`; others run commands as root.
A failed plain `apt-get` invocation establishes that invocation failed, not that installation was impossible.
Several task Dockerfiles inherit private thin base images whose complete build recipes/cache contents are absent
from the pinned public archive. A linked child recipe therefore does not prove the contents of every inherited layer.

Two observed recoveries matter when interpreting this inventory: `mlx-lm-mambacache` installed `mlx-cpu` and `mlx`
and successfully imported `mlx.core` on Linux before failing to find `pytest`; `rudel-task-8e0bd6` recovered from Bun
installation failures through npm tarball downloads and subsequently completed a production build.
CPU-only Nunchaku and Unsloth validation is explicit reference behavior. Source-code error strings, ordinary
compiler errors and expected-negative tests are not themselves classified as missing-environment evidence.

## Task inventory

**Completion** describes which requested work remains feasible, not whether the model's implementation was correct.
**Intent** distinguishes an explicit policy/design choice from an omission whose intent is unknown. A blocked host can
be intentional while the task's dependence on that host is an unresolved mismatch. Each recipe link is pinned.
