# Add a benchmark

A benchmark should define the task, its data and verifier, and the conditions that make a score meaningful. Keep the task independent of a particular harness wherever possible; the runtime composability RFC proposes separating task ownership from episode execution and harness behavior.

## Before contributing

- Reproduce the benchmark's published result in its original implementation when integrating an existing benchmark.
- Add representative examples and a verifier fixture. Check both reward endpoints and malformed input.
- Run `gym env validate NAME` and `gym env test NAME`.
- Run a representative model rollout and inspect the actual trajectory and verifier decision. Compare against a published baseline when possible.
- Record the upstream source/revision, dataset license, split, preparation steps, configuration, and validation limits in the pull request.

Do not add benchmark-specific harness code solely to connect the task to Gym. Put task tools, state, and verification in the resources server; put reusable loop behavior in the agent server. The RFC's proposed Environment Server will own episode protocol and cleanup, but that architecture is not yet implemented as the required contribution path.

For scaffolding and manifest fields, see [New Environment](/contribute/environments/new-environment). Repository checks are in [Contributing](/contribute).
