<Info>
**Goal:** Add a new resources server when no existing scorer can grade the task.

**Time:** Longer than an overlay. Budget a working session for `verify()`, tests, and the five-row artifacts.

**In this guide you will:**

1. Scaffold `resources_servers/<name>/`
2. Implement `verify()` (and tools or state)
3. Add unit tests
4. Produce five example rows, metrics, and rollouts
5. Open a PR that matches CI
6. Add a named benchmark overlay that chains to the new server

Reusing `math_with_judge`, `mcqa`, or similar? Stop and follow [Add a benchmark](/contribute/environments/adding-a-benchmark).
</Info>

<NavButton href="/contribute/environments/onboarding-decision-tree" label="Onboarding decision tree" direction="back" />

An environment is the measurement surface (tasks, verifier, tools, state). Gym config composes it with an agent and a model.

**Prerequisites:** [Development setup](/contribute/development-setup) and a working `env.yaml` from the [Quickstart](/get-started/quickstart). For a full hands-on `verify()` and tool example, work through [Single-Step Environment](/environment-tutorials/single-step-environment) first. Run every command from the repository root.

---

## 1. Scaffold

```bash
gym search resources-servers "task description"
gym env init --resources-server my_server
```

```text
resources_servers/my_server/
+-- __init__.py
+-- app.py                 # VerifierFixture scaffold (see below)
+-- configs/my_server.yaml # instance keys: my_server_resources_server, my_server_simple_agent
+-- data/
|   +-- .gitignore
+-- tests/
|   +-- __init__.py
|   +-- test_app.py
|   +-- verifier_cases.jsonl
+-- requirements.txt
+-- README.md
```

YAML instance names are `{name}_resources_server` and `{name}_simple_agent` (pass the latter as `--agent`).

<Warning>
For in-tree PRs, use `gym env init --resources-server` only. `--environment` / `--reuse-verifier` / `--benchmark` write the experimental manifest contract — details are in the accordion at the bottom of this page.
</Warning>

---

## 2. Implement `verify()`

`gym env init --resources-server` generates a **VerifierFixture** scaffold: `verify()` lives on a `{Name}Verifier` mixin, `VERIFIER_FIXTURE` is exported, and `tests/test_app.py` runs `exercise_verifier_fixture` against `tests/verifier_cases.jsonl`.

<Warning>
The [Single-Step Environment](/environment-tutorials/single-step-environment) tutorial implements `verify()` on `SimpleResourcesServer` with hand-written pytest. That is the pattern used by most production servers (see [`example_single_tool_call`](https://github.com/NVIDIA-NeMo/Gym/tree/main/resources_servers/example_single_tool_call)). Pick one:

1. **Evolve the scaffold** — keep `VERIFIER_FIXTURE` and update `verifier_cases.jsonl`.
2. **Rewrite to SimpleResourcesServer** — replace `tests/test_app.py` so it no longer imports `VERIFIER_FIXTURE`.

Do not mix the two without updating tests.
</Warning>

Scoring (and any tools or session state) lives in `app.py`. Stub:

```python
async def verify(self, body: BaseVerifyRequest) -> BaseVerifyResponse:
    # Read the trajectory from body.response. Return a numeric reward.
    return BaseVerifyResponse(**body.model_dump(), reward=1.0)
```

Handle missing or malformed model output with `reward=0.0` — do not crash the server. Add tools as extra FastAPI handlers on the same class. For session state (`seed_session`, cookies), see [Stateful Environment](/environment-tutorials/stateful-environment). If `simple_agent` is the wrong loop, see [Complex benchmarks](/contribute/environments/adding-a-benchmark#complex-benchmarks).

Worked SimpleResourcesServer example: [Single-Step Environment](/environment-tutorials/single-step-environment). Verification pattern catalog: [Build Verifiers](/build-verifiers).

Set `domain` in the resources-server YAML (`math`, `coding`, `agent`, `knowledge`, `instruction_following`, `long_context`, `safety`, `games`, `translation`, `e2e`, `rlhf`, or `other`). See [Resources Server Fields](/reference/configuration#resources-server-fields).

Complete `README.md` with licensing. The `add-verified-flag` hook sets `verified: false` — leave it.

---

## 3. Tests

At least one test in `tests/test_app.py` is required. The scaffold ships `test_verifier_fixture` plus `verifier_cases.jsonl` — replace or extend those when you change the verify pattern. Cover a passing reward, a failing reward, and empty model output.

```bash
gym env test --resources-server my_server
```

That command runs pytest only. Add `+should_validate_data=true` to also check the five-row artifacts in the next step. CI always sets that flag.

---

## 4. Example data and rollouts

Create `resources_servers/my_server/data/example.jsonl` with **exactly 5** lines **before** collating metrics. New-server example rows typically **do** include `responses_create_params.input` (unlike overlay JSONL that uses `prompt_config`):

```json
{"responses_create_params": {"input": [{"role": "user", "content": "what's it like in sf?"}]}}
```

Add whatever fields `verify()` reads (`expected_answer`, `verifier_metadata`, tools). Reference: [`example_single_tool_call/data/example.jsonl`](https://github.com/NVIDIA-NeMo/Gym/blob/main/resources_servers/example_single_tool_call/data/example.jsonl) and [Single-Step §2](/environment-tutorials/single-step-environment#2-task-preparation).

CI then requires all three files under `resources_servers/my_server/data/`:

| Artifact | Rule |
| --- | --- |
| `example.jsonl` | Exactly **5** rows (often the first five of your train split) |
| `example_metrics.json` | `"Number of examples": 5` |
| `example_rollouts.jsonl` | Exactly **5** rollouts |

Generate metrics:

```bash
gym dataset collate \
  "+config_paths=[resources_servers/my_server/configs/my_server.yaml]" \
  +output_dirpath=data/my_server \
  +mode=example_validation
```

Generate rollouts (servers running):

<Note>
**Before rollouts:** [Development Setup](/contribute/development-setup) (`uv sync --extra dev`) and root `env.yaml` (`policy_base_url`, `policy_api_key`, `policy_model_name`) from the [Quickstart](/get-started/quickstart). Never commit `env.yaml`. Start servers in one terminal, collect in another. `--agent` is `my_server_simple_agent`.
</Note>

```bash
gym env start --resources-server my_server --model-type openai_model
gym eval run --no-serve \
  --agent my_server_simple_agent \
  --input resources_servers/my_server/data/example.jsonl \
  --output resources_servers/my_server/data/example_rollouts.jsonl \
  --limit null
```

Then:

```bash
gym env test --resources-server my_server +should_validate_data=true
```

Worked example: [`resources_servers/example_multi_step`](https://github.com/NVIDIA-NeMo/Gym/tree/main/resources_servers/example_multi_step). `gym env test` (all servers) only discovers directories that contain `README.md`. Do not leave `*conflict*` files under `data/`.

Train and validation dataset entries need a YAML `license` field. The scaffold already sets `license: Apache 2.0` on those slots — update it when you publish real splits. Hugging Face `source:` is the public default; GitLab is NVIDIA-internal. See [Prepare Data](/data).

## 5. Open a PR

- [ ] `tests/test_app.py` and `gym env test --resources-server my_server +should_validate_data=true`
- [ ] Five-row `example.jsonl`, `example_metrics.json`, `example_rollouts.jsonl`
- [ ] `domain` on the server YAML; `license` on train/validation datasets
- [ ] `verified: false` (leave the hook default)
- [ ] SPDX header on every new file
- [ ] `git commit -s` (DCO)
- [ ] `pre-commit run --files resources_servers/my_server/**/*` (stage auto-fixes from ruff / `add-verified-flag` / `update-readme-table`)
- [ ] README with licensing
- [ ] PR description: what the environment measures, how `verify()` works, data source and domain

Reward profiling and a training run are optional for merge. They are stronger evidence before `verified: true`. See [Add a benchmark](/contribute/environments/adding-a-benchmark#6-reward-profiling).

---

## 6. Name the eval

A resources server is the scorer, not the named benchmark. After the server exists, add an overlay under `benchmarks/<name>/` that chains to `resources_servers/my_server/configs/my_server.yaml`. A training mix can live under `environments/<name>/` the same way.

Follow [Add a benchmark](/contribute/environments/adding-a-benchmark) from step 2, pointing `config_paths` at **your** server instead of `math_with_judge`.

<Accordion title="Optional: reward profiling and training">
If you have compute, inspect reward distribution on at least ~500 prompts with 16 responses each (Qwen3-4B, Qwen 30B A3B, or equivalent). For tool-calling, report tool-call metrics vs reward.

A useful training check isolates this environment (for example GRPO with NeMo RL, 64 prompts per step, 16 rollouts per prompt). Include curves and config links in the PR if you run it.
</Accordion>

<Accordion title="Experimental manifest contract">
In-tree environments and benchmarks do not ship `manifest.yaml`. The commands below are implemented but experimental.

```bash
gym env init --environment my_eval --profile custom-gym-verifier
gym env validate my_eval
gym env test my_eval
gym env publish my_eval
```

`--reuse-verifier` requires the reused server to export `VERIFIER_FIXTURE`. Production scorers do not. Reuse them with `config_paths` and `_inherit_from` instead.

The fixture contract (full-reward, zero-reward, malformed, plus reseed when `seeded`) is the local bar on that path. Publication records readiness as `experimental`. CODEOWNERS, immutable versions, and a hosted catalog index are not automated yet.

Integration profiles (`custom-gym-verifier`, `custom-gym-agent-loop`, `external-agent-loop`, `external-rollout-driver`) classify where the episode is driven. They are authored labels, not a runtime dispatcher. See `nemo_gym/environment/manifest.py` and [CLI: gym env init](/reference/cli-commands#gym-env-init).
</Accordion>

<Accordion title="Recommended technical design">
Handlers should be async. Use the NeMo Gym OpenAI client from the top-level `nemo_gym` package, not LiteLLM. Extend `BaseVerifyRequest` / `BaseVerifyResponse` for extra fields. Return tool errors to the model instead of crashing. Pass configuration through Gym YAML, not environment variables.

On multi-step rollouts, propagate `prompt_token_ids`, `generation_token_ids`, and `generation_log_probs` on later model calls. Details: [Single-Step Environment](/environment-tutorials/single-step-environment) and [`AGENTS.md`](https://github.com/NVIDIA-NeMo/Gym/blob/main/AGENTS.md).
</Accordion>
</AccordionGroup>
