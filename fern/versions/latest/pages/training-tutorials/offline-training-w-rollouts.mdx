## Why Offline Training?

**Offline training** uses pre-collected rollouts to improve AI models without real-time exploration. This approach is ideal when:

- You have a working agent that demonstrates good behaviors
- You want reproducible results - same data, consistent training outcomes
- You need cost-effective training - no expensive exploration during training
- You want to capture expert demonstrations - preserve successful patterns
- You have limited compute - more efficient than reinforcement learning

**The offline training pipeline**: Generate rollouts → Filter and process → Train models → Deploy improved agents

## Training Data Types

### Supervised Fine-Tuning (SFT) Data

**Purpose**: Train models to follow successful agent interaction patterns

**Data structure**: Input-output pairs showing complete agent conversations
```json
{
  "messages": [
    {"role": "user", "content": "What's the weather in Paris?"},
    {"role": "assistant", "content": "", "tool_calls": [{"id": "call_1", "type": "function", "function": {"name": "get_weather", "arguments": {"city": "Paris"}}}]},
    {"role": "tool", "tool_call_id": "call_1", "content": "Temperature: 22°C, sunny"},
    {"role": "assistant", "content": "The weather in Paris is 22°C and sunny."}
  ],
  "reward": 1.0
}
```

### Direct Preference Optimization (DPO) Data

**Purpose**: Train models to prefer better responses over worse ones

**Data structure**: Preference pairs with chosen vs rejected responses
```json
{
  "prompt": [{"role": "user", "content": "Solve this math problem: 2x + 5 = 13"}],
  "chosen": [
    {"role": "assistant", "content": "I'll solve for x step by step:\n2x + 5 = 13\n2x = 13 - 5\n2x = 8\nx = 4"}
  ],
  "rejected": [
    {"role": "assistant", "content": "The answer is x = 3"}
  ],
  "reward_margin": 1.0
}
```

## Data Preparation Overview

The offline training pipeline follows this logical flow:

1. Collect rollouts
   - **SFT data**: Use consistent generation (low temperature, single rollout per task)
   - **DPO data**: Use diverse generation (higher temperature, `--num-repeats 2` or more so each task has rollouts to compare)
2. Filter for quality - Remove masked and low-reward rollouts before building SFT data. DPO pairs need the low-reward rollouts as the rejected side, so build them from all unmasked rollouts.
3. Format for training - Convert to SFT or DPO format based on your goals

Each line of a rollouts file from `gym eval run` holds the task (`responses_create_params`), the model's turns as Responses API items (`response.output`), the verifier's `reward`, and the task and repeat indices `_ng_task_index` and `_ng_rollout_index`. A verifier sets `mask_sample: true` when the environment, not the model, failed a sample; its reward is not a valid training signal. The filtering and DPO snippets skip rows with no model turns in `response.output`, such as the results of an environment server that records its own result type (`nemo_user_sim`, for example). Harness agents that run their own tools, such as OpenCode, Pi, or Harbor, record the tool calls but not the tool definitions, so their rows have no `tools`.

## Step 1: Quality Filtering and Curation

Always filter your rollouts first before formatting them for training. Here are example approaches you can customize for your needs:

### Automatic Filtering

```python
import json


def filter_rollouts(
    input_file: str, output_file: str, min_reward: float = 0.5, max_output_items: int | None = None
) -> None:
    """Keep unmasked rollouts that scored at least min_reward."""
    kept = total = 0
    with open(input_file) as f, open(output_file, "w") as out:
        for line in f:
            rollout = json.loads(line)
            total += 1
            if rollout.get("mask_sample"):
                continue  # the environment failed this sample, so its reward is not meaningful
            if rollout.get("reward", 0.0) < min_reward:
                continue
            output = rollout.get("response", {}).get("output")
            if not isinstance(output, list) or not output or not all(isinstance(item, dict) for item in output):
                continue  # no flat Responses items, such as aviary_agent's per-step transitions
            # Opt in to a length cap: tool calls add several items, so successful agent rollouts can run long.
            if max_output_items is not None and len(output) > max_output_items:
                continue
            out.write(line)
            kept += 1
    print(f"Kept {kept}/{total} rollouts")


filter_rollouts("results/rollouts.jsonl", "filtered_rollouts.jsonl", min_reward=0.7)
```

### Manual Curation (Optional)

For critical applications, sample and manually review:

```python
import json
import random


def sample_for_review(input_file: str) -> None:
    """Sample rollouts for manual review."""
    with open(input_file) as f:
        rollouts = [json.loads(line) for line in f]
    
    # Stratified sampling by reward
    low_reward = [r for r in rollouts if r.get('reward', 0) < 0.5]
    mid_reward = [r for r in rollouts if 0.5 <= r.get('reward', 0) < 0.8]
    high_reward = [r for r in rollouts if r.get('reward', 0) >= 0.8]
    
    sample = (random.sample(low_reward, min(10, len(low_reward))) +
              random.sample(mid_reward, min(20, len(mid_reward))) +
              random.sample(high_reward, min(20, len(high_reward))))
    
    with open('manual_review_sample.jsonl', 'w') as out:
        for rollout in sample:
            out.write(json.dumps(rollout) + '\n')
```

<Note>
These are example filtering approaches. Customize the criteria, thresholds, and sampling strategies based on your specific domain and quality requirements.

</Note>

## Step 2: Format for Training

After you have filtered, high-quality rollouts, format them for your chosen training method:

### SFT Data Processing

Rollouts store the conversation as Responses API items: the prompt in `responses_create_params.input` and the model's turns in `response.output`. Training libraries expect Chat Completions messages, so convert both with NeMo Gym's `ResponsesConverter`, the same converter its model servers use. It turns `function_call` items into assistant `tool_calls`, `function_call_output` items into `tool` messages, and `reasoning` items into `<think>` blocks in the assistant content. Filter out items whose `type` is `reasoning` first if you don't want to train on them. The task's `instructions`, when set, become the leading system message. `to_chat` then parses each tool call's `arguments` from a JSON string into a dict, because the Hugging Face chat templates that TRL and NeMo RL apply expect one.

Some Responses fields have no Chat Completions equivalent, and the converter raises `NotImplementedError` on them. `to_chat` drops the two that rollouts commonly carry, a message's `phase` and a reasoning item's `encrypted_content`; any other, such as an image in a tool output, still raises. Readable reasoning `content` becomes the `<think>` text when present; otherwise the snippet uses the reasoning `summary`.

The helper normalizes text messages for chat templates: it maps `developer` to `system`, joins text-only content parts, and supplies empty content on tool-call turns. Invalid or non-object tool arguments become `{}`, matching vLLM's chat-template preprocessing. This is a text-training policy, not a lossless export; inspect it against your trainer's template before training. The snippets skip missing prompts and nested transition outputs rather than inventing the task or flattening separate steps.

Run these snippets in the NeMo Gym environment, in one Python session:

```python
import json

from nemo_gym.openai_utils import NeMoGymResponseCreateParamsNonStreaming
from nemo_gym.responses_converter import ResponsesConverter

converter = ResponsesConverter(return_token_id_information=False)


def chat_representable(item: dict) -> dict:
    """Drop the Responses-only fields that Chat Completions messages cannot hold."""
    item = {key: value for key, value in item.items() if key != "phase"}
    if item.get("type") == "reasoning":
        if item.get("content"):
            item["summary"] = [{"type": "summary_text", "text": part["text"]} for part in item["content"]]
        item.pop("content", None)
        item.pop("encrypted_content", None)
    return item


def to_chat(items: list, tools: list | None = None, instructions: str | None = None) -> dict:
    """Convert Responses API items (and tools and instructions) to Chat Completions messages (and tools)."""
    chat = converter.responses_to_chat_completion_create_params(
        NeMoGymResponseCreateParamsNonStreaming(
            input=[chat_representable(item) for item in items], tools=tools or [], instructions=instructions
        )
    ).model_dump(exclude_none=True)
    for message in chat["messages"]:
        if message["role"] == "developer":
            message["role"] = "system"
        content = message.get("content") or ""
        if isinstance(content, list) and all(part["type"] == "text" for part in content):
            content = "\n".join(part["text"] for part in content)
        message["content"] = content
        for call in message.get("tool_calls", []):
            try:
                arguments = json.loads(call["function"]["arguments"] or "{}")
            except json.JSONDecodeError:
                arguments = {}
            call["function"]["arguments"] = arguments if isinstance(arguments, dict) else {}
    return chat


def prompt_items(rollout: dict) -> list:
    prompt = rollout["responses_create_params"]["input"]
    return [{"role": "user", "content": prompt}] if isinstance(prompt, str) else prompt


def process_sft_data(filtered_rollout_file: str, output_file: str) -> None:
    """Write each rollout as one chat transcript: the prompt followed by the model's turns."""
    with open(filtered_rollout_file) as f, open(output_file, "w") as out:
        for line in f:
            rollout = json.loads(line)
            task = rollout["responses_create_params"]
            chat = to_chat(
                prompt_items(rollout) + rollout["response"]["output"],
                task.get("tools"),
                task.get("instructions"),
            )
            messages = chat["messages"]
            while messages and messages[-1]["role"] != "assistant":
                messages.pop()  # end on the model's last turn, as NeMo RL's SFT loader requires
            if not any(message["role"] == "user" for message in messages):
                continue  # the agent did not record its task prompt
            example = {"messages": messages, "reward": rollout["reward"]}
            if chat.get("tools"):
                example["tools"] = chat["tools"]
            out.write(json.dumps(example) + "\n")


process_sft_data("filtered_rollouts.jsonl", "sft_data.jsonl")
```

### DPO Data Processing

Pair each task's highest- and lowest-reward rollouts. Rollouts of the same task share `_ng_task_index`, so collect with `--num-repeats 2` or more. Build pairs from one run's unfiltered rollouts file: low-reward rollouts are needed as the rejected side, and every run numbers its tasks from 0. Some environments also add a random starting state to each rollout's prompt (blackjack deals a new hand), so the snippet pairs only rollouts that saw the same prompt. This snippet reuses `to_chat` and `prompt_items` from the SFT snippet:

```python
from collections import defaultdict


def create_dpo_pairs(rollout_file: str, output_file: str, min_margin: float = 0.1) -> None:
    """Pair the best and worst unmasked rollouts of each task prompt when their rewards differ enough."""
    by_prompt = defaultdict(list)
    with open(rollout_file) as f:
        for line in f:
            rollout = json.loads(line)
            if rollout.get("mask_sample"):
                continue
            output = rollout.get("response", {}).get("output")
            if not isinstance(output, list) or not output or not all(isinstance(item, dict) for item in output):
                continue
            task = rollout["responses_create_params"]
            prompt_key = json.dumps([task["input"], task.get("instructions"), task.get("tools")], sort_keys=True)
            by_prompt[(rollout["_ng_task_index"], prompt_key)].append(rollout)

    pairs = 0
    with open(output_file, "w") as out:
        for rollouts in by_prompt.values():
            chosen = max(rollouts, key=lambda r: r["reward"])
            rejected = min(rollouts, key=lambda r: r["reward"])
            margin = round(chosen["reward"] - rejected["reward"], 6)  # so 0.3 - 0.2 counts as 0.1
            if len(rollouts) < 2 or margin < min_margin:
                continue
            task = chosen["responses_create_params"]
            prompt = to_chat(prompt_items(chosen), task.get("tools"), task.get("instructions"))
            if not any(message["role"] == "user" for message in prompt["messages"]):
                continue  # DPO needs a recorded prompt separate from each completion
            pair = {
                "prompt": prompt["messages"],
                "chosen": to_chat(chosen["response"]["output"])["messages"],
                "rejected": to_chat(rejected["response"]["output"])["messages"],
                "reward_margin": margin,
            }
            for side in (pair["chosen"], pair["rejected"]):
                while side and side[-1]["role"] != "assistant":
                    side.pop()  # end on the model's last turn, as in the SFT snippet
            if not pair["chosen"] or not pair["rejected"]:
                continue
            if prompt.get("tools"):
                pair["tools"] = prompt["tools"]
            out.write(json.dumps(pair) + "\n")
            pairs += 1
    print(f"Created {pairs} preference pairs from {len(by_prompt)} task prompts")


create_dpo_pairs("results/rollouts.jsonl", "dpo_pairs.jsonl")
```

## Training Integration

After you have your processed data (`sft_data.jsonl` or `dpo_pairs.jsonl`), you can use any post-training framework for SFT or DPO:

### Standard Data Formats

SFT data follows the conversation format used by most training libraries:
```json
{"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
```

DPO data follows TRL's conversational preference format (NeMo RL's DPO expects `context` and ranked `completions` instead):
```json
{"prompt": ["..."], "chosen": ["..."], "rejected": ["..."]}
```

## Validation and Evaluation

### Pre-Training Validation

Before training, validate your data quality by checking:
- **Dataset size**: Sufficient examples for training objectives
- **Reward distribution**: Reasonable range and average quality scores  
- **Length distribution**: Appropriate conversation lengths
- **Task diversity**: Balanced representation across different task types

### Post-Training Evaluation

Test your improved model by generating new rollouts on held-out evaluation tasks:

```bash
# Generate rollouts with improved model
gym eval run --no-serve \
    --agent improved_agent \
    --input evaluation_tasks.jsonl \
    --output post_training_rollouts.jsonl
```

Compare key metrics like average reward, success rate, and task-specific performance against your baseline to measure improvement.

## Best Practices

### 1. Data Quality Over Quantity

```python
# Prefer a smaller set of high-reward rollouts over a large noisy one
filter_rollouts("results/rollouts.jsonl", "filtered_rollouts.jsonl", min_reward=0.8)
```

### 2. Balanced Datasets

Run this on rollouts before formatting them; each rollout's `agent_ref` names the environment's agent that produced it:

```python
import json
from collections import Counter


def balance_dataset(input_file: str, output_file: str, max_per_environment: int = 100) -> None:
    """Cap how many rollouts each environment contributes."""
    counts = Counter()
    with open(input_file) as f, open(output_file, "w") as out:
        for line in f:
            rollout = json.loads(line)
            environment = (rollout.get("agent_ref") or {}).get("name", "unknown")
            if counts[environment] < max_per_environment:
                out.write(line)
                counts[environment] += 1
```

## Troubleshooting

### Problem: Poor Training Data Quality

```
Low average rewards, inconsistent behaviors
```

**Solutions**:
- Increase `min_reward` threshold for filtering
- Generate rollouts with lower temperature (more consistent)
- Add manual curation step
- Improve base agent before data collection

### Problem: Insufficient Data Diversity

```
Model overfits to limited patterns
```

**Solutions**:
- Generate rollouts with higher temperature
- Use more diverse input tasks
- Collect data from multiple agent configurations
- Balance dataset across task types

### Problem: Training Instability

```
Loss doesn't converge, model performance degrades
```

**Solutions**:
- Check data format compatibility with training framework
- Reduce learning rate
- Add regularization
- Filter out extremely long or short conversations
