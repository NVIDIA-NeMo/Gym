Legal Agent Bench uses `benchmarks/legal_agent_bench/config.yaml`. The default
harness is Harbor. LAB uses Gym's general Harbor bridge with native `job`
configuration, while existing `legal_agent_bench::<task_name>` task IDs remain
valid. The collector supplies task and rollout indices; direct `/run` callers
must supply those indices too.

Policy calls pass through the selected Gym Model Server with rollout identity.
Harbor owns verification, ATIF conversion, concurrency, and cleanup. An agent
timeout remains a graded outcome under the shared Harbor bridge's rules.

Benchmark version 0.2.0 pins Harvey LAB commit
`9e9fa7fe126103de1fceb2227b7c70bf59b67f73`: 2,010 tasks, including nested
scenarios and 250 firm-knowledge tasks backed by a shared document corpus.
Skills come from `lab_core/harness/skills`. Historical
example rollouts describe the former 1,749-task snapshot; they are not new
validation evidence.

Preparation verifies the source revision and archive checksum, rejects corpus
paths outside the source asset tree, and caches each shared corpus once.
Generated indexes contain no harness binding. The selected harness is assigned
when Gym collates the dataset. Existing flattened task IDs remain stable.

To prepare a subset, pass `+prepare_script_args.input=/absolute/path/tasks.jsonl`.
The selected rows keep their sampling parameters and the full benchmark index
is left untouched. Preparation fetches only missing tasks and required shared
corpora, with atomic replacement and cross-process cache locking. Cache markers
include the source revision, so old caches cannot silently serve the new pin.

## Sandbox sessions

The LAB resources server creates and cleans up the task sandbox. The native
harness borrows a connection through `AsyncSandbox.serialize()` and
`AsyncSandbox.connect()`. Closing the harness session stops its tool processes
and disconnects; the resources server collects outputs and stops the sandbox.
The resources server also creates and cleans up a separate verifier sandbox.

Docker and OpenSandbox use their existing connection support. Apptainer and
Enroot require the same host and UID; Enroot also requires matching data/runtime directories and a live
init process with its original identity. OpenShell reconnects through the same
gateway and workspace and verifies the sandbox identity.

ECS Fargate sharing requires exec-server mode and a live owner SSH forward on
the same host and UID. Borrowers open independent HTTP clients through that
forward. Disconnecting a borrower releases its client and attempts to delete
its temporary S3 upload objects, including objects left after extraction fails.
The owner retains its task, tunnel, and separately tracked upload objects. This
does not provide a portable ECS connection for workers on different hosts.

Descriptors do not add provider authentication keys. Enroot and OpenShell
descriptors include the sandbox environment, which can itself contain secrets;
treat descriptors as trusted connection metadata and do not publish them.

## Judge profiles and score comparability

Set a nonempty `lab_judges` list in the gitignored root `env.yaml`. One entry
selects single judging with that model. Two entries must be the official pair,
`claude-sonnet-4-6` and `gpt-5.5`. Missing, empty, duplicate-pair and larger
lists fail validation; there is no implicit judge selection.

Each entry requires `model_name` and may specify its own OpenAI-compatible
`base_url`, `api_key`, and `reasoning_effort`:

```yaml
lab_judges:
  - model_name: claude-sonnet-4-6
    base_url: https://your-claude-gateway.example/v1
    api_key: your-claude-key
  - model_name: gpt-5.5
    base_url: https://your-openai-gateway.example/v1
    api_key: your-openai-key
```

If both judges share an endpoint and credentials, configure those once:

```yaml
judge_base_url: https://your-judge-endpoint.example/v1
judge_api_key: your-judge-key
lab_judges:
  - model_name: claude-sonnet-4-6
  - model_name: gpt-5.5
```

Per-judge connection settings override the shared values. Provider route
prefixes may precede the canonical model names. For single judging, keep just
one entry (any supported judge model). An explicitly empty per-judge API key
is preserved for unauthenticated local endpoints. Keep credentials outside
committed YAML.

Migrate existing LAB `judge_model_name` settings to `lab_judges[0].model_name`.
Remove explicit `judge_profile` settings: the profile is derived from the list
and retained in results, rather than configured separately.

With two judges, the full-task reward is the mean of their independent
all-criteria task scores: 0, 0.5, or 1. `all_pass` means both judges passed every
criterion. Single judging produces 0 or 1 in this default `full_task` mode.
With `reward_mode: criteria_pass_rate`, the reward is the mean of the judges'
criterion pass rates (or the single judge's pass rate). For example, judges
passing 2/2 and 1/2 criteria produce reward 0.75 in criterion mode and 0.5 in
full-task mode. Both metrics are retained in the reports regardless of which
one is selected as the reward. Each judge's report is retained; `scores_dual.json` is
written only when both judges finish grading all criteria. Grading errors route
to failure handling rather than becoming completed zero-score tasks. Harbor
collects the declared LAB artifacts, stops the agent environment, then grades
in its separate verifier environment. Writable automatic host log mounts are
rejected for LAB.

The verifier records the source revision, judge profile, per-judge results,
Python/document-library versions, and pandoc version. The image installs the
upstream-pinned pandoc 3.11 with its published checksum and includes `unzip`.
DOCX margin comments are graded with their anchored passages; converter failures
remain ungraded errors. The structured judge schema asks for reasoning before
verdict. These changes and the 2,010-task source refresh require new baselines;
the old PR's single-judge 1,749-task scores are historical evidence.

The LAB tool loop exposes the upstream six workspace tools plus `finish`.
Completion checks only the files the agent claims to have produced, never the
hidden rubric. Missing files reject completion twice before the soft gate
accepts it; the verifier still scores the resulting output. CLI harnesses use
their own tools and termination conventions.

## Native task sessions

`benchmarks/legal_agent_bench/config_native.yaml` selects the native LAB loop.
The unqualified benchmark continues to use Harbor. Native flat rows run through
`single_agent_turn_legacy`; select the harness in configuration, leaving task rows
unchanged.

The LAB resources server stages documents and public skills without mounting a
repository or host output directory. The harness borrows a connection to the task
sandbox. After the harness closes, the resources server captures output, stops
the task sandbox, rejects archive links and
unsafe paths, and runs the verifier in a fresh sandbox. Judge credentials and
hidden criteria are only supplied to verification. Results under
`results/legal_agent_bench` retain the response, tool transcript, output files,
source revision, harness pins, runtime image, judge profile, and grading reports.

Native session artifacts are downloaded and extracted in separate worker processes.
The default limits are 4 GiB per compressed archive, 16 GiB of decompressed data
(including tar metadata and padding), 8 GiB per file, 100,000 entries (including
implicit directories), 4,096 bytes per path, and 64 path components. Each worker
has an 8 GiB memory budget and a 15-minute wall-time/CPU budget. Linux also applies
an address-space limit; resident memory is monitored on all supported hosts.
Invalid or oversized archives fail verification rather than producing a score.
Only successfully extracted files are published; a failed attempt preserves any
previous output. Limits apply separately to agent output and verifier reports.

For larger deliverables, override the relevant fields in the native benchmark's
Resources configuration. Unspecified fields keep their defaults:

```yaml
legal_agent_bench_benchmark_resources_server:
  resources_servers:
    legal_agent_bench:
      archive_limits:
        max_archive_bytes: 8589934592       # 8 GiB compressed
        max_expanded_bytes: 34359738368     # 32 GiB, including tar overhead
        max_file_bytes: 17179869184         # 16 GiB per file
        worker_memory_bytes: 17179869184    # 16 GiB; some providers buffer downloads
        timeout_seconds: 1800
```

These are per-worker ceilings, not reserved capacity. Set task concurrency and
host capacity accordingly. Both transfer and extraction workers are stopped on
cancellation or timeout; the resources server remains responsible for sandbox teardown.

The default session provider is local Docker. The native benchmark preset sets
the resources server's concurrency from `num_samples_in_parallel` (default: `1`).
**Automatic LAB runtime image building requires the Docker CLI and a running
Docker daemon on the Gym host.** It builds from the explicit runtime context when
`sandbox_image` is unset and the selected provider is Docker.

For ECS Fargate, Apptainer, Enroot, OpenSandbox, or OpenShell, replace the provider
configuration and set `sandbox_image` to an accessible, provider-compatible LAB
image prepared from that context. Supplying this image avoids local Docker image
building; changing only the provider does not. With a non-Docker provider and no
`sandbox_image`, LAB rejects setup rather than invoking Docker. Automatic image
building without Docker is not implemented.

ECS reattachment
currently requires the owning Gym host and its live SSH forward; Enroot requires
the same host and UID. OpenShell requires a matching configured gateway. No image
is automatically pushed. Provider availability must be established before claiming
a successful run.

The native adapter retains Responses/tool history and declares a gap for
normalized invocation observations. It is intended for evaluation; no training
or TB21 support is claimed. Session checkpoint recovery restarts the episode.
Native operator rollout stops are unsupported; the Environment Server episode
deadline and session close cancel the host loop and supervise command cleanup.

The native agent time budget includes model calls, activation setup, and tool
staging and execution. When it expires, cleanup must finish before the result
can be graded as incomplete. Cleanup failures remain operational errors.
