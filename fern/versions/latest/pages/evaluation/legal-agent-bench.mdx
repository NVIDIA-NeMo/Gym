Legal Agent Bench uses `benchmarks/legal_agent_bench/config.yaml`. The default
harness is Harbor. LAB uses Gym's general Harbor bridge with native `job`
configuration, while existing `legal_agent_bench::<task_name>` task IDs remain
valid. The collector supplies task and rollout indices; direct `/run` callers
must supply those indices too.

Policy calls pass through the selected Gym Model Server with rollout identity.
Harbor owns verification, ATIF conversion, concurrency, and cleanup. An agent
timeout remains a graded outcome under the shared Harbor bridge's rules.

Benchmark version 0.2.0 pins Harvey LAB commit
`9e9fa7fe126103de1fceb2227b7c70bf59b67f73`: 2,010 tasks, including nested
scenarios and 250 firm-knowledge tasks backed by a shared document corpus.
Skills come from `lab_core/harness/skills`. Historical
example rollouts describe the former 1,749-task snapshot; they are not new
validation evidence.

Preparation verifies the source revision and archive checksum, rejects corpus
paths outside the source asset tree, and caches each shared corpus once.
Generated indexes contain no harness binding. The selected harness is assigned
when Gym collates the dataset. Existing flattened task IDs remain stable.

To prepare a subset, pass `+prepare_script_args.input=/absolute/path/tasks.jsonl`.
The selected rows keep their sampling parameters and the full benchmark index
is left untouched. Preparation fetches only missing tasks and required shared
corpora, with atomic replacement and cross-process cache locking. Cache markers
include the source revision, so old caches cannot silently serve the new pin.

## Judge profiles and score comparability

Set a nonempty `lab_judges` list in the gitignored root `env.yaml`. One entry
selects single judging with that model. Two entries must be the official pair,
`claude-sonnet-4-6` and `gpt-5.5`. Missing, empty, duplicate-pair and larger
lists fail validation; there is no implicit judge selection.

Each entry requires `model_name` and may specify its own OpenAI-compatible
`base_url`, `api_key`, and `reasoning_effort`:

```yaml
lab_judges:
  - model_name: claude-sonnet-4-6
    base_url: https://your-claude-gateway.example/v1
    api_key: your-claude-key
  - model_name: gpt-5.5
    base_url: https://your-openai-gateway.example/v1
    api_key: your-openai-key
```

If both judges share an endpoint and credentials, configure those once:

```yaml
judge_base_url: https://your-judge-endpoint.example/v1
judge_api_key: your-judge-key
lab_judges:
  - model_name: claude-sonnet-4-6
  - model_name: gpt-5.5
```

Per-judge connection settings override the shared values. Provider route
prefixes may precede the canonical model names. For single judging, keep just
one entry (any supported judge model). An explicitly empty per-judge API key
is preserved for unauthenticated local endpoints. Keep credentials outside
committed YAML.

Migrate existing LAB `judge_model_name` settings to `lab_judges[0].model_name`.
Remove explicit `judge_profile` settings: the profile is derived from the list
and retained in results, rather than configured separately.

With two judges, the full-task reward is the mean of their independent
all-criteria task scores: 0, 0.5, or 1. `all_pass` means both judges passed every
criterion. Single judging produces 0 or 1 in this default `full_task` mode.
With `reward_mode: criteria_pass_rate`, the reward is the mean of the judges'
criterion pass rates (or the single judge's pass rate). For example, judges
passing 2/2 and 1/2 criteria produce reward 0.75 in criterion mode and 0.5 in
full-task mode. Both metrics are retained in the reports regardless of which
one is selected as the reward. Each judge's report is retained; `scores_dual.json` is
written only when both judges finish grading all criteria. Grading errors route
to failure handling rather than becoming completed zero-score tasks. Harbor
collects the declared LAB artifacts, stops the agent environment, then grades
in its separate verifier environment. Writable automatic host log mounts are
rejected for LAB.

The verifier records the source revision, judge profile, per-judge results,
Python/document-library versions, and pandoc version. The image installs the
upstream-pinned pandoc 3.11 with its published checksum and includes `unzip`.
DOCX margin comments are graded with their anchored passages; converter failures
remain ungraded errors. The structured judge schema asks for reasoning before
verdict. These changes and the 2,010-task source refresh require new baselines;
the old PR's single-judge 1,749-task scores are historical evidence.

The LAB tool loop exposes the upstream six workspace tools plus `finish`.
Completion checks only the files the agent claims to have produced, never the
hidden rubric. Missing files reject completion twice before the soft gate
accepts it; the verifier still scores the resulting output. CLI harnesses use
their own tools and termination conventions.
