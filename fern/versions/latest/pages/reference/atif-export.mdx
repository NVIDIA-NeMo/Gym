# ATIF Export

For command options and an example, see [`gym eval export`](/main/reference/cli-commands#gym-eval-export).

`gym eval export atif` converts the supported `ng_trajectory` version `1.0` subset into ATIF v1.7 without loading
NeMo Relay. The initial converter accepts a completed root invocation with one initial system/user input phase, exactly one
captured model call per turn, text-only output (including ordered multipart tool results), and unambiguous function-call and
function-result relationships. Model calls may be joined by `model_call_id` or by a unique `(model_ref, response_id)`
pair. It rejects later user/system turns and source records when their status, evidence gaps, content type, invocation
structure, tool correlation, or provider completion evidence would require dropping or guessing information. This strict
boundary means an accepted conversion is complete for the supported source profile; it does not claim that the original
agent harness observed every action outside Gym.

Responses message `phase` values such as `commentary` and `final_answer` are rejected because ATIF v1.7 has no equivalent
field. Namespaced Responses function calls are also rejected because the standard ATIF tool-call fields cannot retain the
separate namespace identity. A missing or null phase or namespace is accepted because it carries no additional source meaning.
Provider-native hosted tools, shell and patch calls, tool search, compaction records, approvals, and additional-tool records
remain outside the initial generic function-call profile and are rejected rather than flattened.

The semantic profile maps ordered messages, reasoning, function calls and results, turn identity and resolution, tool timing,
normalized model identity, and normalized token counts. Training token IDs, log probabilities, and routed-expert metadata are
outside the initial profile and fail conversion rather than being copied into an extension. Captured provider request and
response values are retained opaquely under step-level `extra.nemo_gym.model_call` metadata because ATIF's standard step
fields do not carry those provider-specific payloads. The converter does not parse those raw payloads or use them to
reconstruct the canonical trajectory; the producer-owned `response_metadata` and `token_stats` fields supply completion,
model, and usage evidence. Per-step token fields are preserved when available. Final prompt, completion, and cached-token
totals are emitted only when every model call provides the corresponding field, so unavailable values are never counted as
zero. Each agent step retains the normalized model identity. The root agent model is populated only when
every model-backed step uses the same known model; routed or fallback trajectories keep their model identities on the
individual steps instead.

The strict ATIF reverify path additionally requires complete prompt and completion counts when any supported usage is
present because one Gym response cannot represent partial standard usage. A partial-metric export remains valid ATIF for
other consumers, but Gym reverify rejects it instead of dropping the known counts or reporting a false complete aggregate.

The ATIF `agent.name` comes from each rollout row's `agent_ref.name`. The initial batch exporter accepts one agent identity
per input file because the caller supplies one corresponding agent implementation version. Conversion provenance is kept
under the ATIF root's `extra.nemo_gym` namespace rather than overloading the agent identity fields:

| Metadata | Value | Purpose |
| --- | --- | --- |
| Exporter | NeMo Gym and its package version | Identifies the implementation that created the ATIF file. |
| Source | Gym rollout and `ng_trajectory` schema version | Records the format that was converted. |
| Conversion status | `complete` | Confirms that the supported normalized `ng_trajectory` profile was mapped without omission; it does not attest to the contents of opaque provider payloads. |
| Conversion warnings | Not emitted by strict v1 | Reserved for a future best-effort mode that can describe information it could not represent. |

The default strict converter does not emit partial files or conversion warnings. Unsupported or lossy inputs fail validation.


## Export v2 conversations explicitly

To export a supported `ng_trajectory` version `2.0` rollout, select the compatibility profile:

```bash
gym eval export atif \
    +rollouts_jsonl_fpath=results/rollouts.jsonl \
    +output_dirpath=results/atif \
    +session_id=eval-2026-11-03 \
    +agent_version=1.2.3 \
    +compatibility_profile=v2-conversation
```

Python callers pass `compatibility_profile="v2-conversation"` to `gym_rollout_to_atif`. The default `strict-v1` profile rejects
v2 input. The conversation profile also accepts v1 records using the unchanged strict conversion, so one exporter configuration
can cover a migration. Unknown schema versions and invalid timing boundaries or statuses fail validation.

This profile builds ATIF content from the normalized root invocation conversation. It accepts one completed root invocation,
text and generic function calls with completed results, and exactly one proven captured model call per exported agent step.
It rejects nested invocations, repeated normalized `tool_call_id` values, failed or unfinished tools, and structural or
request-correlation gaps. Unknown identity never becomes a guessed association.

Each native turn must reference one captured model call. Tool groups join through their normalized call IDs and the tools'
requesting `model_call_id`; every tool in a group must agree with the same native turn and model call. Text-only groups join
through a unique persisted assistant message ID in the native turn's answer. The supported native answer anchor shape is a
list of `function_call` items with `call_id`, or one assistant `message` item with `id`. Missing, duplicate or ambiguous
anchors reject the export. Turn order, text and timestamps do not select a match. Known invocation, turn and model instances
must agree. Captured session and assistant-message IDs, when present, must match the native invocation and `source_message_id`.

Native turns remain unchanged under root `extra.nemo_gym.source_turns`. Questions may remain null; native step counts keep
the producer's meaning; native answer and reasoning payloads remain opaque evidence, including fields not represented by
Responses items. Each exported agent step records its `source_turn` association under `extra.nemo_gym`, including the index
in that original turn list and its model-call ID. This profile does not emit the strict-v1 `turn.step_count` metadata because
that field describes cumulative tool-call counts. ATIF step IDs and final step counts still count the exported steps.

The conversation is not asserted to be the exact provider request. Actual captured requests and responses remain unchanged
in each step's `extra.nemo_gym.model_call`; no conversation prefix is inserted as a missing native question. The v2 profile
uses the same model-completion, token-accounting and supported conversation checks as strict v1, without requiring native
turn payloads to duplicate that conversation. A completed tool may retain only a start or a duration without changing its
reported outcome.

The root `extra.nemo_gym.tool_timing` extension retains the original v2 tool records, including nulls and empty measurement
lists, plus capture identity, invocation/turn/model instance identity, model clocks, failure events and source gaps. Its tool records
preserve span/native/parent/requesting-model/failure IDs and each measurement's boundary, source, clock domain and duration
provenance.
Three provenance gaps are accepted when scoped to one exported tool attempt: `tool_agent_instance_unavailable`,
`tool_clock_domain_unavailable`, and `tool_duration_source_unavailable`. They remain in the extension and each produces a
`source_timing_provenance_gap` warning. No missing instance, clock or duration source is invented. Every other source gap
still rejects the export, including missing or ambiguous requesting-model joins and missing execution-attempt identity.

The original values remain available even where the scalar projection cannot express them:

| V2 evidence | Compatibility mapping |
| --- | --- |
| One timing boundary | Known endpoints and duration are copied independently. Executor maps to `executor`, transcript to `artifact`, and lifecycle/event receipt to `harness`. |
| Several timing boundaries | Scalar timing is omitted; all measurements remain in the extension. No boundary is selected implicitly. |
| Empty timing list or unknown duration | Remains unavailable; no zero duration is invented. A reported zero remains zero. |
| Attempt, instance, parent and requesting-model identity; failure links; clocks and detailed sources | Retained in `extra.nemo_gym.tool_timing`; the v1 scalar fields do not express these semantics. |

V2 exports identify their conversion as `ng-trajectory-v2-conversation-to-atif-v1` with `status: partial` and structured
`warnings`. `native_turns_extension_required` identifies the native-turn preservation boundary and distinguishes conversation
content from provider requests. `v2_timing_extension_required` reports the need to read the timing extension; `multiple_timing_boundaries_not_projected`
names each attempt whose scalar timing was omitted. The `partial` status describes the compatibility mapping, not an
unfinished tool. Consumers that ignore the extension lose v2 identity and timing provenance and must not interpret lifecycle
or transcript evidence as executor timing. Gym's ATIF reverification reconstructs the supported conversation; it does not
restore this v2 timing contract.

The exporter validates every row before publishing the output directory and manifest. Rejected v2 input leaves no partial
batch. To roll back a consuming path, keep that producer path explicitly projected to v1 or use the default `strict-v1`
profile with v1 inputs; changing a v2 schema label does not make its records compatible.
