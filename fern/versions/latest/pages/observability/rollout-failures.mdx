---
title: Failure observations
description: Typed boundary failures and bounded event maps without changing outcome policy.
---

Gym records observed failures using `NgFailureEvent` and its model, harness, agent,
resources-server, environment-server and collection boundary subclasses. Existing
handlers, outcome policy, retry budgets and native scoring remain in control.

Each failure gets one stable event ID. `failure_events` maps IDs to observations;
`failure_id` identifies the current failure and `cause_id` links explicit causes.
Foreign exception names and integer HTTP statuses are data, never dynamically
imported classes. Implicit Python context does not become a causal relationship.
Kinds belong to their boundary; a nested provider status does not reclassify a judge failure.

Shared HTTP helpers forward observations on error and successful responses, so
an attempt recovered by an existing retry remains observable. The collector saves
the same metadata beside its existing result/failure records. Old records with no
event metadata retain their existing meaning; the saved-record version stays 1.

Transport bounds may shorten reasons or omit events. Explicit `reason_truncated`
and `cause_truncated` markers distinguish compatible projections from conflicting
facts. Counts of omitted observations are diagnostic lower bounds, not a new metric.
Compatible copies retain the richer observation. Contradictory copies of an ID
are excluded and named in bounded conflict metadata; affected cause references are
marked truncated. At most 16 conflicting IDs are forwarded; overflow is reported as
omitted observations, so downstream exclusion is guaranteed only for retained IDs.
This diagnostic-loss behavior does not change the task outcome.

`observe_failure` records an attempt before retrying. Request-local observation
capture and shared response helpers forward the resulting bounded map. This is
not a new history store, retry engine or policy definition.
