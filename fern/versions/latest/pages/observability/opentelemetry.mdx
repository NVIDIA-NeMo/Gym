# OpenTelemetry

NeMo Gym can emit OpenTelemetry traces, metrics, and logs through
[nemo-lens](https://github.com/NVIDIA-NeMo/Lens), the shared instrumentation library for the NVIDIA
NeMo ecosystem. Telemetry is optional and off by default.

## Why this exists

A single rollout crosses several NeMo Gym processes. The agent server calls the model server, and
both can call the resources server. Each is a separate FastAPI process with its own logs. With
telemetry enabled, one rollout produces **one distributed trace**, and each hop appears as a nested
span:

```text
gym.rollout                         agent server     4.21s
|- HTTP POST                        agent server     3.86s
|  `- POST /v1/responses            model server     3.84s
|     `- gym.model.responses        model server     3.83s
`- HTTP POST                        agent server     0.31s
   `- POST /verify                  resources server 0.30s
      `- gym.verify                 resources server 0.29s
```

This is application telemetry: where time goes, what failed, and how a configuration behaves on
the deployed hardware. It does not replace experiment telemetry such as reward and accuracy, or
the persisted [rollout evidence](/main/observability/rollout-evidence) used to reconstruct an
agent's actions.

## Quick start

Install the optional telemetry dependency and turn telemetry on:

```bash
uv sync --extra dev --extra telemetry
```

```bash
NEMO_GYM_OTEL_ENABLED=1 NEMO_GYM_OTEL_EXPORTER=console \
gym env start --resources-server example_single_tool_call --model-type vllm_model
```

Every server process now writes one JSON object per line to stdout. To send telemetry to a
collector instead, set an OTLP endpoint:

```bash
NEMO_GYM_OTEL_ENABLED=1 OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317 \
gym env start --resources-server example_single_tool_call --model-type vllm_model
```

## What you get

| Signal | Contents |
| --- | --- |
| Traces | One trace per rollout, spanning the agent, model, and resources-server processes |
| Metrics | Rollout and verification durations, verification success rate, active server count, and FastAPI `http.server.*` metrics |
| Logs | Optional Python log records with trace correlation |

## Cost when disabled

Telemetry is off unless you enable it. Instrumentation checks whether its span group is enabled
before building attributes or importing modules. If `nemo-lens` is not installed, Gym continues to
import and run without the telemetry feature.
