# Tavily Search Setup

The [Tavily resources server](https://github.com/NVIDIA-NeMo/Gym/tree/main/resources_servers/tavily_search)
requires credentials that you obtain from [Tavily](https://app.tavily.com), a local
exclusion-policy file, and policy-model and judge-model endpoints that you operate
or are authorized to use.

## Public integration and benchmark reproduction

You can run the generic Tavily integration with your own credentials, exclusion
policy, model endpoints, and task data. The repository includes a small example
dataset for setup checks.

Some NVIDIA benchmark results use private datasets, policies, or endpoints that
are not distributed with NeMo Gym. Those exact results are not publicly
reproducible without independently authorized access to the same artifacts.
The setup below runs the public integration; it does not reproduce an
NVIDIA-internal benchmark configuration.

## Create a Tavily API key

Create an account in the [Tavily dashboard](https://app.tavily.com), choose a plan
that meets your expected request volume, and create your own API key. The server
host must be able to reach Tavily. Keep the key out of source control and logs.

## Create an exclusion policy

`exclude_domains_file_path` is required. NeMo Gym includes a public
[example policy](https://github.com/NVIDIA-NeMo/Gym/blob/main/resources_servers/tavily_search/configs/exclude_domains.example.json)
that uses reserved example domains:

```json
{
  "notices": [
    {
      "properties": [
        {
          "type": "domain",
          "value": "example.com"
        },
        {
          "type": "url_substring",
          "value": "example.invalid/private/"
        }
      ]
    }
  ]
}
```

Use the checked-in file for a smoke test, or copy it to a location outside the
repository and replace the example values with exclusions appropriate for your
application:

- `domain` values are hostnames without a scheme or path. A match also blocks
  subdomains.
- `url_substring` values are case-insensitive substrings matched against the full URL.
- Add more property objects as needed. An exclusion list is application-specific
  and cannot guarantee that all unwanted content is removed.

The resources-server process, including a containerized process, must be able to
read the configured path. Startup fails if the file is missing, malformed, or
contains an invalid domain.

## Configure search and model credentials

Create a repo-root `env.yaml`, which is gitignored, and provide credentials for
services you own or are authorized to use. This example uses the
[OpenAI model server](/main/model-server/openai) for both the policy and judge:

```yaml
tavily_api_key: <your-tavily-api-key>
exclude_domains_file_path: resources_servers/tavily_search/configs/exclude_domains.example.json

policy_base_url: https://api.openai.com/v1
policy_api_key: <your-policy-model-api-key>
policy_model_name: <your-policy-model-name>

search_judge_model_base_url: https://api.openai.com/v1
search_judge_model_api_key: <your-judge-model-api-key>
search_judge_model_name: <your-judge-model-name>
```

The policy model answers the task and calls search tools. The judge model scores
the answer against the task's ground truth. They may use the same provider or
different providers. The OpenAI configuration requires endpoints that serve the
Responses API; for other endpoint types, select a compatible
[model server](/main/model-server) and Tavily config.

## Run

With Gym installed and your services configured, start the public integration:

```bash
gym env start \
    --resources-server tavily_search/tavily_search_judge_openai_model \
    --model-type openai_model
```

In another terminal, run the committed example data:

```bash
gym eval run --no-serve \
    --agent tavily_search_simple_agent \
    --input resources_servers/tavily_search/data/example.jsonl \
    --output results/tavily_search_rollouts.jsonl \
    --limit 1
```

Inspect the search response, policy exclusions, and judge result before using your
own dataset or increasing concurrency.

## Tool-service behavior and compatibility

The same resource exposes `web_search`, `find_in_page`, and `scroll_page` to native
harnesses when `expose_tools_over_mcp: true`. Credentials remain in the resource
process. `tavily_api_key` accepts one key, a list, or a comma-separated pool;
requests and retries rotate through the pool.

Search defaults to 10 results, advanced search, and 2,000-character snippets,
configured through `max_results`, `search_depth`, and `max_result_chars`.
Exclusion JSON uses `notices[].properties[]` entries of type `domain` or
`url_substring`; domain matches include subdomains. Provider error bodies are
neither forwarded to models nor logged.

These behaviors apply to all Tavily configurations:

- Search requests disable Tavily's aggregate answer, and returned aggregate answers
  are discarded. The former `Search Answer` output section is removed because its
  sources cannot be checked against the local policy; agents receive source results.
- Requested and returned URLs, including reported extraction redirects, are checked
  against domain and `url_substring` exclusions. Author/publisher metadata is not
  enforced. A finite exclusion list cannot prevent all online answer exposure.
  Invalid exclusion domains reject the policy at startup with the file and domain
  identified; entries are never silently dropped.
- Rate-limit retries are bounded rather than indefinite. `max_http_attempts` defaults
  to 3 total attempts; retryable HTTP failures, connection errors, incomplete response
  bodies, and timeouts share this budget. Retries use exponential delays starting at
  one second and rotate keys. `http_timeout_s` defaults to 60 seconds per attempt; a shorter
  SDK timeout takes precedence. Exhaustion raises a tool-service error instead of
  returning an empty search. Under sustained rate limits, reduce concurrency or
  explicitly increase the attempt budget.
- Invalid-key (401) and exhausted-quota (432/433) responses try another configured
  key within that same attempt budget. A rejected key is skipped for the rest of
  the current call; if no alternative remains, the call fails immediately.
  Keys are reconsidered on subsequent calls so replenished quota or restored
  access does not require restarting the server. Other non-retryable client errors
  still fail immediately. See [Tavily's error codes](https://help.tavily.com/articles/8645538886-understanding-http-errors).
- The page cache evicts the least recently used page at `max_cached_pages`
  (default 128); zero disables it.
  `max_cached_page_chars` limits stored page content and applies only when caching
  is enabled (including the initial response). `max_scroll_words` caps each response
  independently of caching.
