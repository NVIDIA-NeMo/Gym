# CoreWeave Sandbox Provider

The `cwsandbox` provider runs prebuilt OCI images using the
[CoreWeave Python SDK](https://github.com/coreweave/cwsandbox-client). It implements
sandbox creation, execution, binary file transfer, status, and deletion. Harbor uses
it through the existing `NemoGymSandboxEnvironment` adapter.

## Install and Configure

Install the optional SDK in the environment that runs the Harbor agent:

```bash
uv pip install -e '.[dev,ray,sandbox,cwsandbox]'
```

The Harbor agent requirements include this extra, so isolated `gym env start`
Harbor environments install it automatically. For other Gym callers, `cwsandbox`
is an opt-in extra.

Set `CWSANDBOX_API_KEY` to an authorized CoreWeave Sandbox key. Optionally set
`CWSANDBOX_BASE_URL` for a deployment-specific endpoint. The shipped provider config
reads these variables through Hydra; absent explicit credentials, authentication
falls back to the SDK's own resolution.

Compose the Harbor, provider, and model configs:

```bash
export TERMINAL_BENCH_2_1_TASKS_DIR=/path/to/terminal-bench-2-1/tasks

gym eval run \
  --config responses_api_agents/harbor_agent/configs/harbor_agent_cwsandbox.yaml \
  --config nemo_gym/sandbox/providers/cwsandbox/configs/cwsandbox.yaml \
  --config responses_api_models/vllm_model/configs/vllm_model.yaml \
  --agent harbor_agent --split benchmark \
  --input /path/to/tasks.jsonl --output results/coreweave-rollouts.jsonl
```

Configure the policy model endpoint as usual. Each task must declare a pullable
`environment.docker_image`; images need `bash`, and Harbor directory transfers need
`tar`. Non-root provider execution also needs `su`, and numeric UIDs need `getent`.
The provider starts containers as root for Harbor setup. The default SDK keepalive
replaces the image entrypoint unless `SandboxSpec.entrypoint` is supplied.

## Resources and Lifecycle

CPU and memory requests default to their limits. To reduce scheduling requests,
set `harbor_environment_kwargs.sandbox_provider_options.resource_requests` with
`cpu` and/or `memory_mib`. Requests cannot exceed explicitly supplied limits.
CoreWeave placement can be selected with provider `create.runner_ids`.

Disk quotas cannot be enforced by this SDK API. Requests produce a warning; set
provider `create.strict_resources: true` to reject them instead. The provider
supports GPU resource requests, but the current Harbor sandbox adapter does not
advertise GPU support.

Harbor's config sets a six-hour server lifetime, a 900-second startup budget, and
an 1800-second fallback command timeout. Explicit Harbor command timeouts override
that fallback. SDK request timeouts are separate from the server lifetime; this
integration does not use the removed SDK `max_timeout_seconds` parameter.

Startup waits for running status and an exec probe. Failed or cancelled startup
attempts reclaim any allocated sandbox ID. Harbor stop always terminates and deletes
the sandbox, including when Harbor passes `delete=False`.

## Current Limits

This integration supports single-container tasks. Dockerfile builds, Docker Compose,
shared-volume orchestration, native service endpoints, and native PTY sessions are
not implemented. Terminus-2 uses its existing tmux execution through Harbor.

Although the provider exposes `provider_options.deny_egress`, Harbor's generic adapter
does not advertise enforcement of task-level `allow_internet=false`. Such tasks are
rejected by default; the existing explicit opt-out runs them without an isolation
guarantee. Enabling the provider option alone does not change Harbor validation.
