# Evaluate WebVoyager

WebVoyager evaluates multimodal agents on live public websites. NeMo Gym uses
one `visual_browser` runtime: headed Chromium under Xvfb, Playwright browser
lifecycle and navigation, and visible coordinate input through PyAutoGUI.

Nano Omni and Qwen3.5 use different model-output adapters, but they consume the
same 552 tasks and drive the same browser, proxy/CAPTCHA, action executor, and
Gemini judge. The earlier BrowserGym-compatible path is not included.

## Validation evidence

Full-population runs used the same hash-pinned tasks and `visual_browser`
runtime. The current Nano Omni parsing contract was repeated twice from the
same frozen source and serving recipe:

| Policy | Result | Completeness |
| --- | ---: | --- |
| Qwen3.5-122B-A10B-FP8 | 300/552, 54.35% | 552 valid unique; no missing, invalid, or duplicate-valid tasks |
| Nano Omni `iter_0004622`, parser-faithful r1 | 415/552, 75.18% | 552 valid unique; no missing, malformed, or duplicate tasks |
| Nano Omni `iter_0004622`, parser-faithful r2 | 420/552, 76.09% | 552 valid unique; no missing, malformed, or duplicate tasks |

The Nano Omni repetitions trust the model server's configured reasoning and
tool-call parsers. Gym validates the resulting structured calls, but it does
not repair malformed payloads, infer aliases, or silently clamp action
arguments. The repetitions averaged 417.5/552, or 75.63%, and differed by five
tasks. Treat all scores as end-to-end integration evidence rather than stable
live-site leaderboard claims.

## Install and prepare

Run from a clean Gym checkout on Linux:

```bash
uv lock --check
uv sync --frozen --extra dev
command -v Xvfb
command -v xvfb-run
command -v xclip
uv run --project resources_servers/visual_browser playwright install chromium
./.venv/bin/gym eval prepare --benchmark webvoyager
```

The prepare command downloads the hash-pinned maintained source, verifies its
SHA-256 and 552-task denominator, and writes
`benchmarks/webvoyager/data/webvoyager.jsonl`.

## Configure external services

Keep credentials in environment variables:

```bash
export WA_BROWSER_PROXY_SERVER="proxy-host.example:19407"
export WA_CAPTCHA_PROVIDER="capsolver"
read -rsp "CapSolver API key: " CAPSOLVER_API_KEY
export CAPSOLVER_API_KEY
printf '\n'

export WEBARENA_JUDGE_BASE_URL="https://inference-api.nvidia.com/v1"
export WEBARENA_JUDGE_MODEL="gcp/google/gemini-3-flash-preview"
read -rsp "Judge API key: " WEBARENA_JUDGE_API_KEY
export WEBARENA_JUDGE_API_KEY
printf '\n'
```

Verify the proxy exits through the intended region and preflight the CapSolver
account before running browser tasks.

## Select the policy

For Qwen3.5-122B-A10B-FP8, Gym launches the checked-in TP8 local-vLLM profile:

```bash
./.venv/bin/python benchmarks/webvoyager/prepare.py \
  --profile qwen35_122b_a10b \
  --rollout-output "$PWD/results/webvoyager/qwen/rollouts.jsonl" \
  --force-env
```

For Nano Omni, configure `POLICY_BASE_URL`, `POLICY_API_KEY`, and
`POLICY_MODEL_NAME`, then use `--profile nano_omni`.

The helper writes the private, gitignored
`benchmarks/webvoyager/env.yaml`. Commands run from that directory load it
automatically, so no separate `--config` argument is required.

<Note>

Tokenizer, chat template, multimodal processor, reasoning parser, and
tool-call parser are policy-server assets. They are not loaded by the browser
or judge, and must match the selected model recipe. The configured parsers are
authoritative: Gym validates their structured output but does not repair it.

</Note>

## Start and smoke

```bash
cd benchmarks/webvoyager
../../.venv/bin/gym env prefetch
xvfb-run --auto-servernum --server-args="-screen 0 1920x1080x24" \
  ../../.venv/bin/gym env start
```

From a second terminal in the same directory:

```bash
../../.venv/bin/gym eval run --no-serve -v \
  --limit 1 \
  --concurrency 1 \
  --output ../../results/webvoyager/smoke/rollouts.jsonl
```

The smoke is healthy when it resolves a reward, executes a browser action, and
releases the browser without a masked infrastructure failure.

## Full population and reconciliation

Run all tasks with `--concurrency 1` for one resource process. For throughput,
launch isolated processes or containers; every worker needs a distinct
DISPLAY, HOME, temporary directory, artifact directory, ports, and rollout
file. Do not place multiple PyAutoGUI sessions on one display.

The portable sequential command is:

```bash
../../.venv/bin/gym eval run --no-serve -v \
  --concurrency 1 \
  --output ../../results/webvoyager/full/rollouts.jsonl
```

Merge worker outputs and compute one global result with Gym's standard
aggregation and health-check commands:

```bash
../../.venv/bin/gym eval aggregate \
  --input-glob "../../results/webvoyager/shards/*/rollouts.jsonl" \
  --output ../../results/webvoyager/full/rollouts.jsonl

../../.venv/bin/gym eval health-check \
  ../../results/webvoyager/full \
  --rollouts-file rollouts.jsonl
```

The aggregate command reports scored and dropped coverage from the worker
sidecars, and the health check detects malformed and duplicate rollout
identities. A reportable result has 552 scored rows, no dropped coverage, and
no unresolved health findings.

## Runtime and training safety

Browser leases are acquired and released asynchronously. Synchronous
Playwright calls stay on a session-affine thread, while each headed PyAutoGUI
session remains isolated in its own process or container and X display.
Provider implementations must release leases idempotently and enforce an
external TTL for process or node loss.

Browser-provider, proxy/CAPTCHA, model-server, and judge failures produce
masked retryable samples instead of reward-zero policy examples. Only a
completed trajectory judged unsuccessful is a valid reward-zero sample.

The checked-in profile YAML files and `provenance.json` are the authoritative
source for model-specific protocol, serving parameters, and immutable dataset
identity. Cluster images, scheduler scripts, caches, checkpoint placement, and
large run artifacts are deployment concerns and are intentionally outside this
benchmark tutorial.
