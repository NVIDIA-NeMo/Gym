This tutorial walks through `openair_congestion`, a multi-turn environment in
which a policy reads 5G cell and UE telemetry and chooses one bounded network
control per turn. You will run its causal synthetic replay, inspect the
programmatic verifier, diagnose recorded KPI data, generate deterministic
evidence, and use the standard Gym evaluation and NeMo RL paths.

<NavButton href="/environment-tutorials/stateful-environment" label="Stateful Environment" direction="prev" />

<Note>
The bundled backend is a deterministic synthetic model. It is useful for
resource-server development, controlled policy comparisons, and training
experiments, but it is not a live OpenAirInterface or FlexRIC deployment and
does not establish physical-network fidelity.
</Note>

## What you will build

Each episode repeats one explicit loop:

```text
task row
  |
  v
system instruction + eight tool schemas + current KPIs
  |
  v
policy emits exactly one tool call
  |
  v
resource-server guardrail validates the call
  |
  v
causal deterministic replay applies the setpoint
  |
  v
next KPIs + decomposed programmatic reward
  |
  +---------------------------> next policy turn
```

There is no LLM judge. The environment computes reward from the previous KPI
state, the selected action, the resulting state, and the versioned reward
contract.

## Prerequisites

Clone NeMo Gym and install its development environment:

```bash
git clone https://github.com/NVIDIA-NeMo/Gym.git
cd Gym
uv sync --all-extras --all-groups
source .venv/bin/activate
```

The scripted client, package tests, JSONL inspection, and golden-set generation
run without a model endpoint, GPU, OAI lab, or external simulator.

## 1. Inspect the package

The main files are:

```text
resources_servers/openair_congestion/
├── app.py                         # reset/step/close API
├── backends.py                    # backend contract and selection
├── client.py                      # scripted HTTP client
├── dataset_backend.py             # recorded-data diagnostics
├── generate_example_rollouts.py   # reproducible API trajectories
├── golden_set.py                  # finite-grid single-intervention oracle
├── configs/openair_congestion.yaml
├── data/example.jsonl
└── openair_congestion/
    ├── guardrail.py
    ├── replay_env.py
    ├── rewards.py
    ├── schemas.py
    └── tools.py
```

The YAML config composes:

- `openair_congestion`, which owns episode state, dynamics, guardrails, and
  reward; and
- `openair_congestion_gymnasium_agent`, which alternates model calls with
  resource-server steps.

The default resource settings are:

```yaml
backend: replay
pool_size: 32
max_steps_default: 60
agent_max_steps: 16
session_ttl_s: 3600.0
protocol_violation_penalty: -1.0
```

`agent_max_steps` is the fallback model-turn budget. Keep it aligned with the
task row's `max_steps` so the agent and resource server agree on truncation.

## 2. Run a complete local episode

Run the scripted client:

```bash
python resources_servers/openair_congestion/client.py
```

The client boots an in-process FastAPI server when no Gym server is already
running, then uses the same `/reset`, `/step`, and `/close` endpoints as the
shared Gymnasium agent. A run prints one accepted or rejected action per step
and a finite episode return.

Identical task inputs and action sequences reproduce identical synthetic
trajectories. A code or reward-version change may intentionally change the
numbers.

## 3. Understand the policy contract

A task row supplies a system instruction, function-tool schemas, evaluator
metadata, and a neutral user request. At reset, the server appends current KPI
telemetry. Difficulty, regime, and scenario labels remain evaluator metadata
and are not rendered into the policy message.

The canonical observation schema is in `openair_congestion/schemas.py`:

| Scope | Representative fields |
|---|---|
| Cell | PRB p50/p99, uplink PRB, scheduler latency, connected UE count, PRACH collision rate, Jain fairness, SLA violations |
| UE | offered and delivered Mbps, PRB cap, BLER, MCS, SINR, buffer occupancy, PDB violations, 5QI |
| Episode | time, episode ID, KPI provenance, last action, last reward, last rejection, step index |

The default `replay` path exposes eight tools:

| Tool | Synthetic control |
|---|---|
| `set_scheduler_policy` | PF, RR, or MaxCI scheduling |
| `set_prb_cap` | Persistent PRB cap for an observed UE |
| `set_mcs_bounds` | MCS and BLER target bounds |
| `set_qos_weights` | Per-5QI scheduling weights |
| `set_admission_policy` | Admission threshold; `slice_reservation` must be empty because slices are not modeled |
| `set_handover_trigger` | A3 offset and time-to-trigger |
| `set_ul_power_control` | P0 and fractional path-loss compensation |
| `noop` | Keep current setpoints for one step |

The policy must emit exactly one function call. Missing, malformed, unknown,
or multiple calls terminate the episode with a finite protocol penalty. A
well-formed unsafe call is rejected by the guardrail and scored as a rejected
transition.

Accepted replay controls are persistent setpoints. Supported setpoint changes
can alter later synthetic KPIs; applying the same setpoint again is idempotent.

<Warning>
The tool names describe network controls, but the bundled backend applies
synthetic effects. It does not send OAI or FlexRIC control messages.
</Warning>

## 4. Follow state and reward

The resource server stores one backend episode per cookie-scoped session.
`reset()` reclaims expired sessions, reads the task parameters, starts a
backend episode, and renders its first KPI state.

For each `step()`, the server:

1. parses exactly one tool call;
2. validates its schema, topology references, and safety bounds;
3. applies the accepted setpoint to deterministic replay;
4. constructs the next KPI state;
5. computes and commits the reward transactionally; and
6. returns the next observation and termination state.

A failed reward computation does not partially advance an episode. Normal
completion, truncation, protocol failure, and explicit close release the
session. Inactive sessions left by a hard client crash are reclaimed after
the configured lease.

Every successful backend step contains the `openair_v1` reward version, raw
measurements, weighted terms, and scalar total. Protocol violations instead
receive the configured fixed penalty. The terms cover SLA violations,
throughput, Jain fairness, PRB/access/fairness/buffer pressure, action
magnitude, and rejected actions.

Always compare policies on the same task manifest, backend, reward version,
horizon, and decoding settings.

## 5. Choose the right replay backend

| Backend | Action changes the next state? | Appropriate use |
|---|---:|---|
| `replay` | Yes, within synthetic dynamics | Development, controlled evaluation, SFT/GRPO experiments |
| `dataset_replay` | No | Data ingestion, reward recomputation, contract diagnostics |

The default `replay` backend is causal within its synthetic dynamics: an
accepted setpoint can change future synthetic KPIs.

`dataset_replay` serves the recorded next observation even when the current
policy chooses a different action. It marks results `training_usable: false`
and `diagnostic_only: true`.

<Warning>
Do not use `dataset_replay` as an on-policy GRPO environment or as evidence
that one policy controls the network better than another. It contains no
counterfactual next state for an action that was not recorded.
</Warning>

### Inspect the checked-in recording

Copy the config so the default replay setup remains unchanged:

```bash
cp resources_servers/openair_congestion/configs/openair_congestion.yaml \
  /tmp/openair_congestion_dataset.yaml
```

Set these resource-server keys in the copy:

```yaml
openair_congestion:
  resources_servers:
    openair_congestion:
      backend: dataset_replay
      dataset_path: data/fixtures/sample_provided.jsonl
      cell_capacity_mbps: 60.0
```

Dataset paths are relative to `resources_servers/openair_congestion/`. Select
the sample's `lab_run_a` episode in a temporary task file:

```bash
jq -c '.scenario_id = "lab_run_a"' \
  resources_servers/openair_congestion/data/example.jsonl \
  > /tmp/openair_dataset_tasks.jsonl
```

Start an inference-only policy:

```bash
gym env start \
  --config /tmp/openair_congestion_dataset.yaml \
  --model-type openai_model \
  --model "$MODEL_NAME" \
  --model-url "$MODEL_BASE_URL" \
  --model-api-key "$MODEL_API_KEY"
```

In another activated terminal, collect one diagnostic rollout:

```bash
gym eval run --no-serve \
  --agent openair_congestion_gymnasium_agent \
  --input /tmp/openair_dataset_tasks.jsonl \
  --output results/openair_dataset_diagnostics.jsonl \
  --limit 1 \
  --num-repeats 1
```

This validates ingestion and exposes guardrail and reward diagnostics. It is
not a causal policy evaluation.

### Use your own nested KPI-snapshot JSONL

Place the data at a reproducible package-relative location:

```bash
mkdir -p resources_servers/openair_congestion/data/user
cp /absolute/path/my_5g_measurements.jsonl \
  resources_servers/openair_congestion/data/user/my_5g_measurements.jsonl
```

Then replace the resource-server keys in the copied config:

```yaml
openair_congestion:
  resources_servers:
    openair_congestion:
      backend: dataset_replay
      dataset_path: data/user/my_5g_measurements.jsonl
      cell_capacity_mbps: 60.0
```

Each nested KPI-snapshot JSONL row is one timestep. Rows sharing an
`episode_id` form an episode and require at least two observations. At minimum,
each row needs a non-empty `cells` list; every cell needs
`prb_util_dl_p50` and a non-empty `ues` list; every UE needs
`delivered_mbps`.

Set `kpi_source_mode` explicitly for measured snapshots. If omitted, it
defaults to `replay` and the observation is stamped synthetic.

```jsonl
{"episode_id":"run_a","step":0,"kpi_source_mode":"measured","recorded_action":{"name":"noop","arguments":{}},"cells":[{"cell_id":0,"prb_util_dl_p50":0.55,"ues":[{"ue_id":0,"offered_mbps":20.0,"delivered_mbps":18.0,"bler":0.05,"sinr_db":12.0}]}]}
{"episode_id":"run_a","step":1,"kpi_source_mode":"measured","cells":[{"cell_id":0,"prb_util_dl_p50":0.70,"ues":[{"ue_id":0,"offered_mbps":20.0,"delivered_mbps":16.0,"bler":0.08,"sinr_db":10.0}]}]}
```

When `step` is present, every row in that episode must provide a unique integer;
the loader sorts those rows by `step`. Malformed topology, duplicate IDs,
fractional integer fields, and non-finite values fail with source provenance.

An optional `recorded_action` is validated and returned as diagnostic metadata;
it does not control the prerecorded next state. Stored scalar rewards are
ignored. The backend recomputes reward from the served before/after
observations, the current evaluation action, guardrail result, and configured
reward contract. This still provides no counterfactual next state for a
different action.

Select the custom episode in the temporary task file:

```bash
jq -c '.scenario_id = "run_a"' \
  resources_servers/openair_congestion/data/example.jsonl \
  > /tmp/openair_dataset_tasks.jsonl
```

Run the same `gym env start` and `gym eval run` commands from the previous
subsection. The temporary config and task file now point at the custom JSONL.

## 6. Extend the environment

### Add a KPI

1. Add the field and bounds to `openair_congestion/schemas.py`.
2. Parse or derive it in `dataset_backend.py` and label its provenance as
   measured, estimated, placeholder, or synthetic.
3. Populate it in `openair_congestion/replay_env.py`.
4. Render it in `openair_congestion/render.py` only if the policy should see it.
5. If it affects scoring, add an auditable term and version the reward contract.
6. Update fixtures, documentation, and focused tests.

### Add a tool

1. Define its function schema and bounds in `openair_congestion/tools.py`.
2. Add topology and safety checks in `openair_congestion/guardrail.py`.
3. Give it deterministic, parameter-sensitive, persistent replay effects, or
   reject it when the synthetic topology cannot represent the action honestly.
4. Update prompts, examples, fixtures, baselines, and focused tests.

## 7. Generate deterministic evidence

Regenerate the five scripted trajectories through the actual HTTP surface:

```bash
PYTHONPATH=.:resources_servers/openair_congestion \
  python resources_servers/openair_congestion/generate_example_rollouts.py
```

The output at `data/example_rollouts.jsonl` records one compact scripted run
per example. Regenerate and test it to check wiring and reproducibility; it is
not policy-quality evidence.

Run the package and Gymnasium-agent tests:

```bash
pytest resources_servers/openair_congestion/tests -q
pytest responses_api_agents/gymnasium_agent/tests/test_app.py -q
```

Generate the finite-grid golden set:

```bash
PYTHONPATH=.:resources_servers/openair_congestion \
  python resources_servers/openair_congestion/golden_set.py \
  --out results/openair_congestion_golden_set.jsonl
```

For each deterministic decision state, the script evaluates a bounded action
grid, applies one candidate, coasts with `noop`, and records the best value and
margin over inaction. This is a reproducible reward-and-dynamics sanity oracle
for that grid and horizon. It is not a universal multi-step optimum or evidence
that a real model understands telecom control.

## 8. Evaluate and profile a hosted policy

Start the environment with an OpenAI-compatible endpoint:

```bash
gym env start \
  --resources-server openair_congestion \
  --model-type openai_model \
  --model "$MODEL_NAME" \
  --model-url "$MODEL_BASE_URL" \
  --model-api-key "$MODEL_API_KEY"
```

In another terminal, use the standard Gym evaluation commands:

```bash
gym eval run --no-serve \
  --agent openair_congestion_gymnasium_agent \
  --input resources_servers/openair_congestion/data/example.jsonl \
  --output results/openair_congestion_rollouts.jsonl \
  --limit 5 \
  --num-repeats 2

gym eval profile \
  --inputs results/openair_congestion_rollouts_materialized_inputs.jsonl \
  --rollouts results/openair_congestion_rollouts.jsonl
```

`gym env start` and `gym eval run` evaluate the endpoint; they do not update
its weights. Keep the same tasks, backend, reward version, horizon, decoding
settings, and repeats when comparing policies. Treat infrastructure, parsing,
and invalid-call failures as failures, not as `noop`.

## 9. Evaluate a local checkpoint

For a checkpoint compatible with the generic local-vLLM configuration:

```bash
gym env start \
  --resources-server openair_congestion \
  --model-type local_vllm_model \
  --model /absolute/path/to/checkpoint

gym eval run --no-serve \
  --agent openair_congestion_gymnasium_agent \
  --input resources_servers/openair_congestion/data/example.jsonl \
  --output results/openair_trained_checkpoint.jsonl \
  --num-repeats 2
```

Some checkpoints require a model-specific chat template or vLLM tool-call
parser. Copy a compatible config under
`responses_api_models/local_vllm_model/configs/` and select it with
`--model-type`.

## 10. Connect causal replay to NeMo RL

The trainable model, tokenizer, optimizer, and SFT/GRPO parameters belong in a
NeMo RL job configuration, not in the resource-server YAML. Use the current
[NeMo RL GRPO tutorial](/tutorials/training-tutorials/nemo-rl-grpo) as the
schema authority.

The Gym portion of the job should enable Gym and reference the training model
and OpenAir configs:

```yaml
env:
  should_use_nemo_gym: true
  nemo_gym:
    config_paths:
      - responses_api_models/vllm_model/configs/vllm_model_for_training.yaml
      - resources_servers/openair_congestion/configs/openair_congestion.yaml
```

Set the base model or checkpoint in the NeMo RL model section. Use causal
`replay`, disjoint training and evaluation manifests, and a fixed evaluation
contract across noop, scripted, SFT, and GRPO policies. This contribution does
not ship a validated OpenAir-specific NeMo RL job YAML, so do not copy an
unrelated environment's hyperparameters without validation.

## Limitations

<Note>
Replay is a deterministic synthetic approximation, not a live OAI/FlexRIC
deployment or physical-network model. `dataset_replay` is non-causal and
diagnostic-only. Golden-set and scripted-rollout evidence checks environment
behavior; learned-policy quality requires separate empirical evaluation.
</Note>
