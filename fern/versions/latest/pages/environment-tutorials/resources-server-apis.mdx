# Resources Server APIs

NeMo Gym resources servers support two episode interfaces. Choose the interface based on who should control the interaction loop and when the environment needs to return rewards.

| Interface | Episode flow | Choose it when |
|---|---|---|
| Native | `seed_session()` → agent loop → `verify()` | The agent should own tool execution and model turns, and the environment computes one final reward. |
| Gymnasium | `reset()` → model response → `step()` → repeat | The environment must inspect every model response and decide the next observation, reward, or stopping condition. |

Any agent can use either interface if it calls the matching HTTP endpoints and preserves the resources server's session cookie. The built-in `simple_agent` and `gymnasium_agent` are convenience implementations, not restrictions on which agents you can use.

<Note>
Single-step grading works with either interface. Use the native API when final verification is enough. Use Gymnasium when you want the environment's behavior to compose naturally with multi-step games, scripted users, or per-step rewards.
</Note>

## Native API: `seed_session()` and `verify()`

The native API separates the agent loop from reward computation:

```text
POST /seed_session
agent calls the model and any resources-server tools
POST /verify
```

`SimpleResourcesServer` exposes these methods:

```python
async def seed_session(
    self,
    body: BaseSeedSessionRequest,
) -> BaseSeedSessionResponse:
    ...

async def verify(
    self,
    body: BaseVerifyRequest,
) -> BaseVerifyResponse:
    ...
```

- **`body` in `seed_session()`** contains fields used to initialize an episode. Define a subclass of `BaseSeedSessionRequest` for fields such as an initial board or sandbox image. The default implementation is a no-op.
- **`body.responses_create_params` in `verify()`** is the original model request.
- **`body.response` in `verify()`** is the completed model response, including the trajectory accumulated by the agent.
- **Custom task metadata** requires a `BaseVerifyRequest` subclass. Declare fields such as `answer` or `expected_state`; undeclared fields are not retained by the base Pydantic model.
- **`request: Request`**, when added to either method signature, gives stateful implementations access to the session ID.

Choose this interface when:

- Existing resources-server endpoints should act as model tools.
- The agent owns tool dispatch, retries, turn limits, or other orchestration.
- Reward is computed once from the completed trajectory or final environment state.
- You are pairing the server with `simple_agent` or a custom agent that speaks `/seed_session` and `/verify`.

### Minimal native server

This stateless server grades one answer. It inherits the default no-op `seed_session()` and implements the required `verify()` method.

```python
from nemo_gym.base_resources_server import (
    BaseVerifyRequest,
    BaseVerifyResponse,
    SimpleResourcesServer,
)
from resources_servers.gymnasium import extract_text


class AnswerVerifyRequest(BaseVerifyRequest):
    answer: str


class AnswerServer(SimpleResourcesServer):
    async def verify(self, body: AnswerVerifyRequest) -> BaseVerifyResponse:
        predicted = extract_text(body.response).strip()
        return BaseVerifyResponse(
            responses_create_params=body.responses_create_params,
            response=body.response,
            reward=float(predicted == body.answer),
        )


if __name__ == "__main__":
    AnswerServer.run_webserver()
```

The built-in `simple_agent` calls `/seed_session`, runs its model and tool loop, and calls `/verify` exactly once at the end.

## Gymnasium API: `reset()` and `step()`

The Gymnasium API gives the environment control after each model response:

```text
POST /reset
model response → POST /step
model response → POST /step
... until terminated or truncated
```

Subclass `GymnasiumServer` and implement `step()`. Override `reset()` only when the environment needs initialization or an initial observation.

```python
async def reset(
    self,
    metadata: dict,
    session_id: str | None = None,
) -> tuple[str | None, dict]:
    ...

async def step(
    self,
    action: NeMoGymResponse,
    metadata: dict,
    session_id: str | None = None,
) -> tuple[str | None, float, bool, bool, dict]:
    ...
```

- **`action`** is the model's response for the current step. Use `extract_text(action)` for text, or inspect `action.output` for structured function calls.
- **`metadata`** contains extra top-level fields from the input JSONL row, such as `answer`, `category`, or task settings. It does not include `responses_create_params`.
- **`session_id`** identifies the rollout and keys per-episode state. Stateless environments can ignore it.

`reset()` returns `(observation, info)`. A non-`None` observation is appended as a user message before the first model call.

`step()` returns `(observation, reward, terminated, truncated, info)`:

- **`observation`**: the next user message, or `None` when no message is needed.
- **`reward`**: reward for this step. `gymnasium_agent` sums step rewards for the episode.
- **`terminated`**: `True` when the episode reaches a natural terminal state.
- **`truncated`**: `True` when a limit or timeout cuts the episode short.
- **`info`**: diagnostic metadata and optional `tool_outputs` returned to the agent.

Choose this interface when:

- The environment decides what the model observes next.
- Every model response must be validated or executed before continuing.
- Rewards are naturally assigned per step.
- The environment owns termination and truncation decisions.
- You are pairing the server with `gymnasium_agent` or a custom agent that speaks `/reset` and `/step`.

### Minimal Gymnasium server

This is the same stateless answer grader expressed as a one-step Gymnasium environment:

```python
from resources_servers.gymnasium import GymnasiumServer, extract_text


class AnswerEnv(GymnasiumServer):
    async def step(self, action, metadata, session_id=None):
        predicted = extract_text(action).strip()
        reward = float(predicted == metadata["answer"])
        return None, reward, True, False, {}


if __name__ == "__main__":
    AnswerEnv.run_webserver()
```

Returning `terminated=True` makes `gymnasium_agent` stop after the first response.

## State Management

Both interfaces use the resources server's session middleware. It assigns a unique `session_id` cookie and the agent sends that cookie on subsequent calls in the same rollout. Store mutable state under that ID so concurrent rollouts do not share episode data.

### Native state

Add `Request` to endpoint signatures, read `SESSION_ID_KEY`, and define a per-session mapping on the server:

```python
from typing import Any

from fastapi import Request
from pydantic import Field

from nemo_gym.server_utils import SESSION_ID_KEY


class StatefulServer(SimpleResourcesServer):
    session_state: dict[str, Any] = Field(default_factory=dict)

    async def seed_session(self, request: Request, body: SeedRequest):
        session_id = request.session[SESSION_ID_KEY]
        self.session_state[session_id] = initialize(body)
        return BaseSeedSessionResponse()

    async def verify(self, request: Request, body: VerifyRequest):
        session_id = request.session[SESSION_ID_KEY]
        try:
            reward = grade(self.session_state[session_id], body)
            return make_verify_response(body, reward)
        finally:
            self.session_state.pop(session_id, None)
```

### Gymnasium state

`GymnasiumServer` provides `self.session_state`. The framework passes the session ID directly to `reset()` and `step()`:

```python
class StatefulEnv(GymnasiumServer):
    async def reset(self, metadata, session_id=None):
        self.session_state[session_id] = initialize(metadata)
        return "Environment ready.", {}

    async def step(self, action, metadata, session_id=None):
        state = self.session_state[session_id]
        reward, done = apply_action_and_score(state, action)
        return None, reward, done, False, {}
```

State can range from:

- **Stateless**: grade a math answer directly from the response and task metadata.
- **Lightweight**: store a counter, game board, or conversation state in memory.
- **Heavyweight**: associate each session ID with a browser, database, or Docker container.

The isolation guarantee depends on using the session ID as the key. Do not put rollout-specific mutable data in an unkeyed server attribute.

### Session cleanup

- **Native API**: `SimpleResourcesServer` does not automatically clear custom state after verification. Remove state in `verify()`, preferably in a `finally` block, and close external resources there.
- **Gymnasium API**: when `step()` returns `terminated=True` or `truncated=True`, `GymnasiumServer` calls `close_session()` and removes the entry from `self.session_state`.
- **Heavyweight state**: override `close_session()`, release the external resource, and call `await super().close_session(session_id)`.

```python
async def close_session(self, session_id):
    container = self.session_state.get(session_id, {}).get("container")
    if container is not None:
        await container.stop()
    await super().close_session(session_id)
```

Make sure the environment itself returns a terminal or truncated result before the agent's `max_steps` is exhausted. Also use timeouts or stale-session reclamation for external resources so client failures cannot leak them indefinitely.

## YAML Configuration

The resources server definition is the same for both interfaces. The paired agent determines which endpoint protocol is used.

<Tabs>
<Tab title="Native">

```yaml
answer_env:
  resources_servers:
    answer_env:
      entrypoint: app.py
      domain: knowledge

answer_env_agent:
  responses_api_agents:
    simple_agent:
      entrypoint: app.py
      resources_server:
        type: resources_servers
        name: answer_env
      model_server:
        type: responses_api_models
        name: policy_model
      datasets:
      - name: example
        type: example
        jsonl_fpath: resources_servers/answer_env/data/example.jsonl
```

</Tab>
<Tab title="Gymnasium">

```yaml
answer_env:
  resources_servers:
    answer_env:
      entrypoint: app.py
      domain: knowledge

answer_env_agent:
  responses_api_agents:
    gymnasium_agent:
      entrypoint: app.py
      resources_server:
        type: resources_servers
        name: answer_env
      model_server:
        type: responses_api_models
        name: policy_model
      max_steps: 10
      datasets:
      - name: example
        type: example
        jsonl_fpath: resources_servers/answer_env/data/example.jsonl
```

</Tab>
</Tabs>

The agent's `resources_server.name` must match the top-level resources server instance name. For Gymnasium environments, set `max_steps` high enough for normal episodes while still providing a safety bound.
