The Slurm executor is the only executor today. It targets clusters with [Pyxis](https://github.com/NVIDIA/pyxis): every service and the driver run in `srun --container-image` steps, so each one uses the container image in its own config.

## What the executor needs

- **On the machine you submit from**, when `compute.<name>.hostname` is set to a different machine: `ssh` and `rsync`. Authentication must work without prompts (the connection runs with `BatchMode=yes`, so use keys or an agent) and unknown host keys are accepted on first contact (`StrictHostKeyChecking=accept-new`). Gym opens one SSH master connection and reuses it for the whole submit.
- **On the cluster login node**: `sbatch`, plus `sacct` and `squeue` (with `--me`, Slurm 20.11 or later) if a benchmark is [resumable](/orchestration/how-to/resumable-runs).
- **On the compute nodes**: Pyxis, and network access to pull container images and, when `gym_install` is used, to clone the repository and install `uv`.
- **When `hostname` is unset, or equals the current machine's hostname**: nothing is copied over SSH. Commands run locally and files are copied locally. Use this when you submit from the login node.

## Submission sequence

1. Validate benchmark names and, when the collector is on, check its Gym telemetry settings and resolve its token. A missing or empty token disables remote export with a warning; destination settings are required only when remote export remains enabled. These checks run before `--dry-run` prints anything.
2. Allocate the submission identity: `gym-job-<UTC timestamp>-<6 hex>`, which is also the run directory's name. The random suffix keeps two submits in the same second from sharing a directory, which would otherwise let the copy step erase the first one's scripts.
3. Render one script per benchmark and stage it locally, in a temporary directory, with its `logs/` and `artifacts/` directories.
4. Open the connection and check that every mount source path exists (see [Troubleshooting](/orchestration/troubleshooting#a-mount-source-does-not-exist)).
5. Copy the staged tree to `<job.output_path>/<gym_job_id>/`. Over SSH this is `rsync -az --delete`; locally, an existing target directory is replaced.
6. Run one `sbatch --parsable` per benchmark in a single shell session, each reporting its own benchmark name, exit status, and output, so one failure cannot shift later benchmarks onto the wrong job ID.
7. Build the record and [persist it](/orchestration/job-records).

A benchmark whose `sbatch` fails is recorded with its error and no job ID. The others are unaffected.

## Run directory layout

```text
<job.output_path>/gym-job-20260101T120000Z-a1b2c3/
├── gym-job.json                 # submission record
├── resolved-config.yaml         # config as submitted (host: values written as references)
└── <benchmark>/
    ├── job.sh                   # the sbatch script (mode 0600)
    ├── logs/
    │   ├── <service>-<slurm job id>.log
    │   └── driver-<slurm job id>.log
    ├── artifacts/
    │   └── rollouts.jsonl       # plus the sibling files gym eval run writes
    ├── model-calls/             # captured model calls (observability on by default)
    ├── otel/                    # collector.yaml and exported *.jsonl, when the collector is on
    └── .gym_*                   # resume bookkeeping, when resumable
```

The staged tree is given mode 0755 so other users can read the run directory, for example a collection job under another account. `job.sh` remains owner-only and contains no resolved task environment values. Log files carry the Slurm job ID, so a resumed job in the same directory keeps the earlier jobs' logs.

## Private task environments

NeMo Gym writes task environments to `environment.json` (0600) in a benchmark-specific directory with 0700 access permissions, under `job.output_path/.gym-private-<run-path-hash>`. Directories may retain an inherited setgid bit; group and other access remain forbidden. Each submission gets its own store, including when different users share an output root. The store is inside the writable output root and outside every run directory, so sharing or exporting a run does not copy its credentials. Before copying a fresh run, Gym validates private-directory ownership and permissions and probes file creation there without writing credentials. The rendered script names the private path, without including its values.

Both local and SSH submits restrict the environment inherited by `sbatch`. Each driver, model service and collector loads its private environment after `srun` starts the task, inside the container when one is used. The task image must provide `python3`. Environment mappings, including `host:` values and forwarded credentials, do not become scheduler command arguments or stored job scripts. A submit with no hostname, or the current machine's exact hostname, captures implicit caller defaults. Task and image values take precedence over these defaults. SSH submits capture no implicit defaults.

Explicit `forward_env` values and the configured remote telemetry token override task/image defaults. A caller-present, nonprotected name selected by `driver.container_env` is also restored privately as an override in the driver only; it participates in the driver's `runtime:` lookup before role assignments. Services and the collector keep their own task/image precedence. Role `host:` and `lit:` assignments apply last. Every `runtime:VAR` reads the launched task's value plus its explicit private overrides, before role assignments, and fails before workload execution if that source is absent. It never falls back to an implicit caller default. Caller-only runtime credentials therefore need explicit forwarding, a driver container selection, or a `host:` assignment. This preserves task `PATH` and arbitrary scheduler/device/MPI context against implicit caller values, while explicitly selected credentials override stale image placeholders.

Caller capture excludes these protected placement names even when listed in `forward_env`: `SLURM_*`, `PMI_*`, `PMIX_*`, `OMPI_COMM_WORLD_*`, `MV2_COMM_WORLD_*`, `MPI_LOCAL*`, `CUDA_VISIBLE_DEVICES`, `NVIDIA_VISIBLE_DEVICES`, and the rank variables `RANK`, `LOCAL_RANK`, `WORLD_SIZE`, `LOCAL_WORLD_SIZE`, `GROUP_RANK`, `ROLE_RANK`, `ROLE_WORLD_SIZE`, and `NODE_RANK`. Shell context such as `PWD` and `HOSTNAME`, and Gym's allocation and resume variables, also remain those of the running job. Explicit forwarding of other names is an intentional override; it is not classified by credential-like spelling.

Slurm `extra_args` on compute configurations and node pools cannot set `export`, `export-file` or `get-user-env`, including underscore spellings and abbreviated option names. These options can reimport a login environment or bypass private delivery. Keys must be single option names; directive values cannot contain line breaks. Use `forward_env` and the driver/service `env` mappings instead. Store-reader `srun` calls also restrict their scheduler environment. Verify a canary submission against the site's actual accounting configuration before forwarding production credentials.

The restricted scheduler environment preserves the nonsecret placement inputs `SLURM_ACCOUNT`, `SLURM_PARTITION`, `SLURM_QOS`, and `SLURM_RESERVATION`, which Slurm documents as [srun input environment variables](https://slurm.schedmd.com/srun.html#SECTION_INPUT-ENVIRONMENT-VARIABLES). This also supports submit recipes that resolve account and partition from these variables. `SBATCH_*`, `SALLOC_*`, and `SRUN_*` defaults remain rejected by name before fresh copying and at each scheduler client, including an SSH target. Set those options in compute/node-pool configuration or reader placement arguments, then unset the ambient option. The error never prints its value. Other allocation outputs, such as `SLURM_JOB_ID`, remain available where the reader needs them.

The private file remains available across concurrent tasks and automatic follow-up allocations. A resubmit refreshes it under the run's existing no-live-job lock. A saved script records only the names of driver container selections captured when rendered. Reusing it requires those inputs to remain set, even after private-file cleanup; restore the missing variables or submit a new run. An explicitly supported rerendering route uses the current selections. Keep its directories owner-only; a missing, symlinked or permissive file prevents task execution. After every job and step of the benchmark has ended, remove that benchmark's private directory. A later explicit resubmit creates it again from the caller's credentials. Never include the private store in shared copies or exports.

Explicit private values override image-baked environment values directly. Caller-present driver container selections travel through the driver's private payload, never through scheduler environments or value-bearing arguments. Caller-absent or protected selections retain native Pyxis forwarding so compute-host runtime values can take precedence over image defaults, even when a role maps that same name through `runtime:`. The field remains in the saved configuration. Implicit local defaults do not override image values.

The private payload and script marker use contract version 3. A new launcher's resubmit path refuses older saved scripts before refreshing credentials, including version 1 scripts with an outside-root private path and version 2 scripts without driver-scoped overrides. Submit a new run, or use an explicitly supported rerendering route; the launcher does not silently relocate old stores or rewrite an incompatible pinned script. Existing active jobs and their follow-ups keep their original scripts and private stores until terminal cleanup.

## The job script


`gym eval submit --dry-run` prints each script. Their structure is always the same:

```text
#!/bin/bash
<#SBATCH directives>

<resume prologue>        only when resumable
<node and Ray setup>     only when the job needs it
<service steps>
<health checks>
<driver step>
```

### Directives

| Directive | Source |
| --- | --- |
| `--job-name=gym-<benchmark>` | the benchmark name |
| `--account` | `compute.<name>.account` |
| `--time` | `compute.<name>.walltime`, if set |
| `--chdir=<benchmark dir>` | the benchmark's directory in the run directory, so `logs/...` resolves there |
| `--partition`, `--nodes`, `--ntasks-per-node`, `--gpus-per-node` | the node pools: one set for the whole allocation, with `--nodes` the sum of the pools' `nodes` |
| any `--key=value` | `extra_args` on the compute and on its pools |

### Service steps

Each service is one background `srun --overlap` step, so services and the driver share the allocation. A step runs in the service's container with `--no-container-mount-home`, applies the service's `env` to that command only, mounts what `mounts` lists, and writes its output to `logs/<name>-$SLURM_JOB_ID.log`. The script records each step's PID so a health check can notice a service that died during startup.

The collector, when enabled, is started first, ahead of the model services, so its scrape covers their startup. It runs as a host process by default rather than in a container.

### Health checks

For each service with a health check, the script polls `http://<host>:<port><path>` every 5 seconds, for `timeout_seconds / 5` attempts. If the service process exits first, or the attempts run out, the job exits with status 1 and no benchmark runs. A vLLM service gets `/health` on its own port automatically. Set `health_check.timeout_seconds` high enough for model download and load; the default is 60.

### Driver step

The driver is one more `srun --overlap` step, in `driver.container`, with the benchmark's directory mounted at the same path as on the host. Without that mount, a run would write its artifacts into the container's temporary filesystem and lose them when the step ended.

Inside one `bash -c`, in order:

1. If `gym_install` is set: install `uv`, clone the repository to a temporary directory, check out `ref`, create a virtual environment, and `uv sync --locked` (with `--extra telemetry` when Gym telemetry is on). The step changes into the checkout so a benchmark's relative paths resolve.
2. If `prepare` is non-empty: `gym eval prepare <overrides>`.
3. `gym eval run` with `+output_jsonl_fpath=<benchmark dir>/artifacts/rollouts.jsonl`, `--model-type <policy_model_type>` when a policy is set, and the flattened `run` overrides. Or, when the benchmark has a `command`, that script instead.
4. When the benchmark has `export` entries, and `gym eval run` exited 0: `python3 -m nemo_gym.orchestration.export_step <exporter> ...` for each one, in the same step. It runs the same exporter as `gym eval export` and keeps the outcome in a result file. The exit code of `gym eval run` goes to `<benchmark dir>/eval.exit` and stays the job's exit status; each export's outcome goes to `<benchmark dir>/exports/<exporter>.result.json`. See [export](/orchestration/configuration#export).

The job's exit status is the driver's. While the driver runs, the script checks every service step every 5 seconds; the OTel collector is not checked. If a service step exits first, the script sends the driver `TERM` and the job exits with status 1. Service steps run with `--kill-on-bad-exit=1 --wait=1`, so a step with several tasks, such as a `vllm_pd` tier or a Ray worker pool, ends as soon as any one task exits; the collector's step keeps Slurm's defaults. When the job ends, Slurm stops the service steps.

## Where services run

The driver runs on the first node of the allocation, or on the first node of the policy service's pool when the policy is pinned. The rules for the services:

| Situation | Placement |
| --- | --- |
| Single-node allocation | Everything shares the node. |
| Multi-node, vLLM service without `node_pool` | Spans every node. See [Multi-Node vLLM](/orchestration/how-to/multi-node-vllm). |
| Multi-node, other unpinned service | One node, beside the driver. |
| Service with `node_pool` | Only the nodes of that pool. See [Node Pools and Ray](/orchestration/how-to/node-pools-and-ray). |

For anything that spans nodes or is pinned, the script resolves the allocation's hostnames with `scontrol show hostnames`, so addresses are never needed in the config. It exports `HEAD_NODE_IP` and `RAY_HEAD_NODE_IP` when a vLLM service spans nodes, and `GYM_POOL_<POOL>_NODES` for each node pool when services are placed by pool.

## Dry-run output

`--dry-run` prints `[dry-run] remote run dir: <path>` and then, for each benchmark, the full script between `=` rules. With the collector on it also prints that benchmark's rendered `otel/collector.yaml`. It does not stage, copy, or queue anything and writes no record. These checks also apply to dry runs: remote export needs `otel.endpoint`, `otel.service_name`, and the token variable. A missing or empty token switches the dry run to local-only collection with a warning.
