## Architecture and routing

Each resource server is an HTTP service registered from YAML. The agent or environment server runs the policy and produces a rollout; the configured resource server receives the rollout at `verify()`, extracts the assistant output or tool/session trace, calls any configured judge, and returns a `reward` plus diagnostic fields. Shared server lifecycle, model APIs, rollout collection, and `agent_ref` routing are in the root `nemo_gym/` and shared `responses_api_*` packages.

A JSONL row normally contains `responses_create_params` (Responses API request fields) plus environment-specific top-level task fields. `agent_ref` identifies the configured agent by name; it is routing metadata for the rollout collector, not a verifier input. With multiple agents/configs registered in one run, rows can select different agents/environments. The collector also has `agent_map` override/fan-out support; its precedence is `agent_map[<row value>]`, `_default`, row `agent_ref`, then `task_source` resolution. Some environments have specialized row schemas or single-agent defaults, so their examples omit `agent_ref`.
