## mkdocs-blogging-plugin Project Introduction and Goals

`mkdocs-blogging-plugin` is a MkDocs plugin that turns a documentation site into a blog. It generates blog index pages that list selected documentation pages sorted by their git commit timestamps (or explicit front-matter dates), with support for client-side pagination, tags, multiple blog categories, pluggable themes (card/button layouts), and custom Jinja templates. It integrates with MkDocs via the standard `BasePlugin` hooks and registers itself under the `blogging` entry point. This task reconstructs the package from scratch: the Python package, its packaged HTML/JS template assets, and packaging metadata.

## Natural Language Instructions (Prompt)

1. Create an importable Python package `mkdocs_blogging_plugin` with an empty `__init__.py` (no exports, no side effects), and modules `config.py`, `plugin.py`, and `util.py`.
2. `config.py` defines `BloggingConfig`, a plain holder for per-category blog settings that takes a config dict and reads keys with defaults: `dirs` (list, default `[]`), `size` (int, default `10`), `sort` (dict, default `{"from": "new", "by": "creation"}`), `paging` (bool, default `True`), `show_total` (bool, default `True`), `template` (str, default `None`), `theme` (dict, default `None`), and `full_content` (bool, default `False`). Also declare these attributes at class level.
3. `util.py` defines a `Util` class that: caches `GitPython` `Repo(...).git` handles by directory path (searching parent directories for the repository root); provides `get_git_commit_timestamp(path, is_first_commit=False)` (memoized with `lru_cache`) that returns an integer Unix timestamp of the commit that created the file (using `git log` with `format="%at"`, `diff_filter="A"`, `follow=True`, taking the oldest of possibly multiple creation commits) or of the most recent commit (limit `n=1`), falling back to `time.time()` with a logged warning when the path is not in a git repo, git logs are unreadable, or git is unavailable; and a static `get_localized_date(timestamp, day_only, format=None, _locale=None)` that converts a timestamp with `datetime.fromtimestamp`, returns `strftime` output when a custom `format` is given, otherwise uses `babel.dates.format_date`/`format_datetime` with `"short"` format, resolving the default locale via `locale.getlocale` (Python ≥ 3.11, with `getdefaultlocale` for older versions) and defaulting to `"en_US"` when unset.
4. `plugin.py` defines a module-level `get_config_scheme()` function returning a MkDocs `config_scheme` tuple based on the `BloggingConfig` defaults: `dirs` (list), `size` (int), `sort` (dict), `paging` (bool), `show_total` (bool), `template` (str), `theme` (dict), `full_content` (bool), plus global-only options `meta_time_format` (str, default `None`), `time_format` (str, default `None`), `locale` (str, default `None`), `features` (dict, default `{}`), and `categories` (list, default `[]`), all via `mkdocs.config.config_options.Type`.
5. `plugin.py` defines regexes matching the placeholders embedded in markdown pages: one for `{{ blog_content [<category>] }}` (category restricted to alphanumerics, `-`, `_`; case-insensitive; empty category means `global`) and one for `{{ tag_content }}`; a list `THEMES = ["card", "button"]` of supported theme names; and a `SCRIPTS` string loaded at import time from the packaged asset `templates/pagination.js` wrapped in `<script>` tags.
6. Define `BloggingPlugin(BasePlugin)` whose `__init__` sets the config scheme, instantiates `Util`, and initializes state: site URL and global settings, template context captured from MkDocs, tag templates/state, tags index URL, a `categories` dict of `BloggingConfig` keyed by name (starting with behavior to be filled by config reading), a `pages` dict keyed by category name with entries `{"html": None, "pages": []}` (with `"global"` pre-created), and cached Jinja templates.
7. Implement `read_in_config(global_config)`: it is idempotent (returns early if categories are already read); requires `site_url` in the MkDocs config, raising `mkdocs.exceptions.PluginError` with an instructive message when missing; reads global settings `meta_time_format`, `time_format`, `locale` (falling back to the site's `locale`), and `features`; builds the `global` category from the plugin config and additional named categories from the `categories` list (dicts containing `name`), warning when `categories` is not a list; raises `PluginError` if the theme enables `navigation.instant` while any category has paging on; normalizes missing `sort` keys to `"new"`/`"creation"`; validates `theme` dicts (warning and clearing theme when a name is missing, unknown, or when a custom template also exists — template wins with a warning); builds a Jinja `Environment` with a `FileSystemLoader` over the packaged templates directory plus the parent directories of any custom templates (custom templates resolved relative to the MkDocs config file directory); selects per-category templates (custom template name, else `blog-<theme>-theme.html`, else `blog.html`); loads `blog-tags-index.html` and `blog-tags.html`; and when the `tags` feature defines an `index_page`, computes `tags_index_url` as the site URL plus the index page path without extension, appending `.html` when `use_directory_urls` is `False`.
8. Implement MkDocs event hooks: `on_serve` (reads config, watches custom template files for live reload, returns the server); `on_config` (resets `pages`, `categories`, and `tags` for live-reload correctness, then reads config); `on_template_context` (stores the template context and returns it); `on_page_markdown` (when the `tags` feature is on and the page meta has `tags`, stamps the page with a timestamp, collects string tags into a tags-to-pages mapping when the meta value is a list — warning and skipping otherwise — and optionally inserts rendered tag HTML into the markdown, at the top by default or at the bottom preceded by `\n<br/>\n` when `insert == "bottom"`).
9. Implement `on_page_content`: skips pages whose meta has a truthy `exclude_from_blog`; for each category, checks whether the page's `src_path` lies under one of the category's `dirs` and appends a timestamped page to that category's page list (at most once per category).
10. Implement `on_post_page`: replaces the blog placeholder with the rendered blog HTML (generated lazily, cached per category) and appends the pagination scripts; raises `PluginError` when the placeholder names an unknown category; and when tags are enabled, replaces the tag-content placeholder with rendered tag-index HTML (tag names and per-tag pages sorted by the pages' git timestamps, respecting the global `sort.from` direction), cached across pages.
11. Blog HTML rendering (`generate_html(category)`) sorts category pages by their `git-timestamp` meta (descending when `sort.from == "new"`), and renders the category's Jinja template with context: `pages`, `page_size`, `paging`, `is_revision` (true when sorting by revision), `show_total`, `theme_options` (from `theme.get("options")`), `index_url`, `show_tags`, `mkdocs_context`, and `full_content`.
12. Timestamp stamping (`with_timestamp(page, by_revision)`) prefers the page meta `time` then `date` key (parsed via a helper that accepts `datetime`/`date` instances or strings parsed with `meta_time_format`, returning `None` otherwise), falling back to the git commit timestamp (first commit unless sorting by revision); it stores `page.meta["git-timestamp"]` and `page.meta["localized-time"]` (via `Util.get_localized_date` with the configured `time_format` and `locale`).
13. Package the Jinja templates `blog.html` (base layout with styles, a `render_blog` macro fallback, pagination markup
