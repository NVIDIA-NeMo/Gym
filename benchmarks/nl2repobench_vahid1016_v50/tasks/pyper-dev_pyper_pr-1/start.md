## Pyper Project Introduction and Goals

Pyper ("Concurrent Python made simple") is a pure-Python framework for concurrent and parallel data processing built on functional-programming patterns. It targets ETL systems, data microservices, and data-collection workloads. Users decorate ordinary Python functions with a single `task` decorator and compose them into pipelines via the `|` operator; the framework dispatches each task behind the scenes using asyncio tasks, threads, or processes depending on whether the function is asynchronous, synchronous IO-bound, or synchronous CPU-bound, and whether `multiprocess=True` was requested.

Goals:

- Provide one intuitive API (`pyper.task`, `pyper.Pipeline`, `pyper.AsyncPipeline`) unifying threaded, multiprocessed, and asynchronous execution.
- Lazy, queue-based execution: each stage pulls items from an input queue and pushes results to the next stage's queue, enabling efficient concurrent pipelines with worker fan-out and backpressure (`throttle`).
- Support branching tasks (a task producing many outputs per input), joining tasks (a task consuming all previous results as one input), bound arguments, pipeline composition, and piping pipelines into consumer functions.
- Safety: automatic resource clean-up, error propagation to the caller, graceful shutdown on interrupts; no third-party runtime dependencies (only `typing_extensions` on Python < 3.10).
- Ship as the importable package `pyper`, distributed under the distribution name `python-pyper`.
