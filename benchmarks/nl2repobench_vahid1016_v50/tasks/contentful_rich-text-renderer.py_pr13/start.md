## Rich Text Renderer Project Introduction and Goals

This project reconstructs `rich_text_renderer`, a small dependency-free Python library that renders Contentful "Rich Text" documents into HTML. Contentful's Rich Text fields are plain dictionaries (JSON) describing a tree of block nodes (headings, paragraphs, lists, quotes, embedded assets/entries) and inline nodes (text, marks, hyperlinks). The renderer walks that tree, dispatching each node to a renderer class looked up by a mapping keyed on `nodeType` (or `type` for marks), and returns an HTML string.

Goals:
- Provide a top-level `RichTextRenderer` with sensible default HTML mappings covering all standard block, inline, hyperlink, and embedded-resource node types.
- Allow full customization: any mapping (including the `None` fallback for unknown node types) can be overridden with user-supplied renderer classes.
- Provide a `NullRenderer` that raises for unmapped node types by default, but can be replaced to silently skip them.
- Keep the code pure-Python with no runtime dependencies beyond the standard library.

3. `base_node_renderer.py` defines the base class `BaseNodeRenderer(object)` whose `__init__(self, mappings=None)` assigns `self.mappings = mappings if mappings is not None else {}` (an empty dict, not a shared default). It provides the lookup helper `_find_renderer(self, node)` which returns `self.mappings.get(node.get("nodeType", None), None)` and, if not `None`, returns an *instance* of the renderer class constructed with `self.mappings`; returns `None` when the key is missing or maps to `None`.
4. `document_renderers.py` defines `DocumentRenderer(BaseNodeRenderer)` whose `render(self, document)` iterates `document["content"]`, finds a renderer for each node, skips nodes with no renderer, renders the rest, and joins results with `"\n"`.
5. `null_renderer.py` defines `NullRenderer(BaseNodeRenderer)` whose `render(self, node)` raises `Exception` with the message `"No renderer defined for '{0}' nodes"` formatted with the node type. Its `_node_type(node)` helper returns `node["nodeType"]` if present, else `node["type"]` if present, else the node itself.
6. `block_renderers.py` defines:

   - `HeadingOneRenderer` through `HeadingSixRenderer` overriding `_render_tag` to `"h1"`…`"h6"` respectively.
   - `ParagraphRenderer` (`"p"`), `OrderedListRenderer` (`"ol"`), `UnorderedListRenderer` (`"ul"`), `ListItemRenderer` (`"li"`), `BlockQuoteRenderer` (`"blockquote"`) — all overriding `_render_tag` but inheriting the `<tag>content</tag>` rendering.
   - `HrRenderer(BaseNodeRenderer)` whose `render(_node)` returns the literal `"<hr />"`.
   - `HyperlinkRenderer(BaseBlockRenderer)` whose `render(node)` returns `'<a href="{uri}">{content}</a>'` with `node["data"]["uri"]` and the standard block content rendering.
   - `EntryBlockRenderer(BaseNodeRenderer)` whose `render(node)` returns `"<div>{0}</div>"` formatted with `node["data"]["target"]` (string conversion of the embedded entry object).
   - `AssetHyperlinkRenderer(BaseBlockRenderer)` with a class-level `ANCHOR_HTML = '<a href="{0}">{1}</a>'`. Its `render(node)` reads `asset = node["data"]["target"]` and: if the asset's class name (via `asset.__class__.__name__`) equals `"Asset"` it renders as a Contentful SDK asset; elif the asset is a `dict` it renders as a hash (validating that `"fields"` exists and contains `"file"`, otherwise raising `Exception`); otherwise raises `Exception` with a message of the form `"Node target is not an asset - Node: {0}"`. Asset rendering resolves the URL (`asset.url()` or `asset["fields"]["file"]["url"]`) and the text (the node when given, so its children get rendered via `_render_content`, otherwise the asset title). A shared `_render(markup, url, text, formatted=True)` applies block-content rendering to the text when `formatted` is true, then formats the markup. Note the exact control flow and the dict-validation condition should mirror the described behavior; validation errors are raised as generic `Exception`s.
   - `AssetBlockRenderer(AssetHyperlinkRenderer)` with class-level `IMAGE_HTML = '<img src="{0}" alt="{1}" />'`. Both `_render_asset` and `_render_hash` check `contentType` on the asset file: if it contains `"image"`, they return the image markup with the file URL and the asset title (no content formatting); otherwise they fall back to the superclass (hyperlink) rendering. Class-name dispatch again uses `__class__.__name__ == "Asset"` rather than importing the Contentful SDK.
7. `text_renderers.py` defines:
   - `TextRenderer(BaseNodeRenderer)` whose `render(node)` deep-copies the node, then for each mark in `node.get("marks", [])` looks up a renderer by the mark's `"type"` key (its `_find_renderer` uses `node.get("type", None)` instead of `"nodeType"`) and, if found, sets `node["value"] = renderer.render(node)` so marks nest left-to-right. Finally it returns `node["value"]`. Deep copying prevents mutation of the input document.
   - `BaseInlineRenderer(BaseNodeRenderer)` whose `render(node)` returns `"<{tag}>{value}</{tag}>"` with `_render_tag` defaulting to `"span"` and `node["value"]` as content.
   - `BoldRenderer` (`"b"`), `CodeRenderer` (`"code"`), `ItalicRenderer` (`"i"`), `UnderlineRenderer` (`"u"`), each overriding only `_render_tag`.

User-supplied `mappings` are merged over the defaults via `dict.update`. Its `render(document)` finds a renderer for the given document node and delegates to it (raising via `NullRenderer` for unknown root types).
