## funcparserlib Project Introduction and Goals

`funcparserlib` is a recursive descent parsing library for Python based on functional combinators, converted from the parsing combinators language taught in the University of Cambridge "Introduction to Functional Programming" course (from ML into Python). Its primary focus is parsing little languages and external DSLs. Parsers built with it are pure-Python LL(\*) parsers: users start from a few primitive parsers, combine them with combinators (`+`, `|`, `>>`, unary `-`, `many`, `maybe`, `oneplus`, etc.), assign complex parsers to variables to model grammar rules, and finally invoke `Parser.parse(tokens)`.

The library has no external runtime dependencies. It consists of three functional modules:

* `funcparserlib.lexer` — a tiny regexp-based lexer generator with token position tracking (`make_tokenizer`, `TokenSpec`, `Token`, `LexerError`).
* `funcparserlib.parser` — the parser combinators DSL (`Parser` class and primitives/combinators, including `NoParseError` and the internal `_Ignored` value type).
* `funcparserlib.util` — a small helper (`pretty_tree`) for rendering pseudo-graphic trees.

Goals for this reconstruction: produce an importable, type-hinted (`py.typed` present) package with the public API below, matching observable behavior including longest-parsed-prefix error reporting via `NoParseError`, plus Poetry-based build metadata so the package can be installed.

5. `Token(type, value, start=None, end=None)`: attributes `type`, `value`, `start`, `end` (each position a `(line, column)` tuple or `None`); `repr` is `Token('type', 'value')`; equality compares `type` and `value` only (and returns `False` against `None`); `str` renders like `1,1-1,5: type 'value'` when positions exist, otherwise `type 'value'`; a `name` property returns `value`; `pformat()` returns a fixed-width formatted line using position, type, and value columns.

On match it yields a `Token` with 1-based start position and computed end position (tracking line breaks: lines increment by newline count; when the match spans newlines the new column is the offset after the last newline, otherwise column advances by match length). If nothing matches it raises `LexerError` with the 1-based `(line, col)` and the text of the current line. The yielded stream must be iterable lazily (a generator).
