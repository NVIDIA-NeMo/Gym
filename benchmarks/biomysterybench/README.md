# BioMysteryBench

[BioMysteryBench](https://www.anthropic.com/research/Evaluating-Claude-For-Bioinformatics-With-BioMysteryBench) evaluates agents on real-world bioinformatics tasks with objective ground-truth answers.

This benchmark contains the utilities required to prepare the benchmark as [Harbor tasks](https://www.harborframework.com/docs/tasks) for NeMo Gym's `harbor` environment server and `opencode_agent` harness.

## Usage

Run the following commands from the repository root. Build and push the task environment image to a registry accessible to your OpenSandbox deployment (replace the image reference below):

```shell
export BMB_DOCKER_IMAGE="<registry>/biomysterybench:<tag>"
docker build --file benchmarks/biomysterybench/Dockerfile --tag "${BMB_DOCKER_IMAGE}" --platform linux/amd64 benchmarks/biomysterybench
docker push "${BMB_DOCKER_IMAGE}"
```

Prepare the task folders by calling the adapter directly:

```shell
uv run --project benchmarks/biomysterybench \
  python -m benchmarks.biomysterybench.harbor.adapter \
  --output-dir "${PWD}/benchmarks/biomysterybench/data" \
  --docker-image "${BMB_DOCKER_IMAGE}"
```

> [!tip]
> Use `--data-dir <local-source-directory-or-huggingface-repo>` to select the source dataset and `--overwrite` to rebuild completed task folders. Run the adapter with `--help` for all options.

> [!tip]
> Add `--skip-data` when task data is supplied separately (for example, baked into the task image or mounted externally via the sandbox provider).

> [!warning]
> Preparation downloads `problems.csv` first, then fetches each task's `data/<id>.zip` only when that task needs conversion. Completed tasks are reused without fetching their archives. Hugging Face downloads require access to [Anthropic/BioMysteryBench-full](https://huggingface.co/datasets/Anthropic/BioMysteryBench-full); authenticate with `uvx hf auth login` if required. Add `--limit 1` to convert at most one task and fetch at most its archive; this does not remove tasks generated by earlier invocations. Archives are downloaded during preparation, before `gym eval run`.

Set `OPENSANDBOX_DOMAIN` and `OPENSANDBOX_API_KEY` for your deployment. The sandbox must be able to reach Gym's model server on the evaluation host.

The `gym eval run` command below reads the generated task folders and prepares its inputs and run configuration automatically.

Configure the verifier's judge:

```shell
export JUDGE_MODEL=openai/nvidia/zai-org/glm-5.2
export JUDGE_MODEL_API_BASE=https://inference-api.nvidia.com/v1
export JUDGE_MODEL_API_KEY="${NVINF_API_KEY}"
```

Run the benchmark evaluation:

```shell
gym eval run "${PWD}/benchmarks/biomysterybench/data" \
  --agent opencode_agent --sandbox opensandbox \
  --model-type openai_model \
  --model nvidia/nvidia/nemotron-3-ultra \
  --model-url https://inference-api.nvidia.com/v1 \
  --model-api-key "${NVINF_API_KEY}" \
  --resume --concurrency 8 --num-repeats 4 \
  --output "${PWD}/benchmarks/biomysterybench/logs/rollouts.jsonl"
```

For a limited manual smoke run, use `--limit 1 --num-repeats 1 --concurrency 1` in place of the full-run repeat and concurrency settings, and choose a separate output such as `benchmarks/biomysterybench/logs/smoke.jsonl`. Inspect the trajectory, verifier logs, reward, and health report before increasing the task count. The session harness uses Gym's model server; its policy model name is the endpoint's model ID, without the legacy `nvinf/` OpenCode provider prefix.

### Configuration Variables

| Variable | Type | Description |
| --- | --- | --- |
| `--output-dir` | Adapter argument | Directory for generated Harbor task folders. Pass this directory as Gym's positional task target. |
| `--docker-image` | Adapter argument | Task image accessible to the sandbox deployment. |
| `--output` | Gym argument | Rollout output path. Reuse the same path and material settings when resuming. |
| `--model`, `--model-url`, `--model-api-key` | Gym arguments | Policy endpoint's model ID, base URL, and API key. |
| `--num-repeats` | Gym argument | Rollouts per task; the full-run example explicitly preserves four repeats. |
| `OPENSANDBOX_DOMAIN` | Environment variable | OpenSandbox service endpoint. |
| `OPENSANDBOX_API_KEY` | Environment variable | OpenSandbox service API key. |
| `JUDGE_MODEL` | Environment variable | Judge model used to score the agent's response. This must use [LiteLLM](https://docs.litellm.ai/) provider prefixes. |
| `JUDGE_MODEL_API_BASE` | Environment variable | API base URL for the judge model. |
| `JUDGE_MODEL_API_KEY` | Environment variable | API key for the judge model. Optional for self-hosted models. |
| `JUDGE_ATTEMPTS` | Environment variable | Judge calls tried before the trial is left without a reward, `3` by default. |
| `JUDGE_TIMEOUT` | Environment variable | Seconds per judge call, `300` by default. |
| `JUDGE_MAX_TOKENS` | Environment variable | Token limit of the judge's answer, reasoning included, `16384` by default. |

## Dataset Reference

### Source

The adapter relies on the HuggingFace dataset.
See [Anthropic/BioMysteryBench-full](https://huggingface.co/datasets/Anthropic/BioMysteryBench-full) for source structure.

### Harbor

The adapter writes one Harbor directory containing all converted tasks. There
are no dataset splits. Each generated task starts from
[`task-template/`](./harbor/task-template); `task.toml`, the instruction, and the
judge prompt are rendered with task-specific values. The matching source
archive is extracted into `environment/data/`.

```text
harbor-bmb/
└── bmb-task__<task id>/
    ├── task.toml
    ├── environment/
    │   └── data/
    │       └── <extracted task data files>
    ├── instruction.md
    └── tests/
        ├── grade.py
        ├── prompt.txt
        └── test.sh
```

- `task.toml`: [Harbor task configuration metadata](https://www.harborframework.com/docs/tasks#configuration--metadata), including the Docker image and timeouts.
- `environment/data/`: The extracted data files made available to the agent.
- `instruction.md`: The task-specific question presented to the rollout agent.
- `tests/prompt.txt`: The task-specific judging prompt, including the private answer rubric.
- `tests/grade.py`: LLM-based verifier that grades the final trajectory response and writes a numeric reward.
- `tests/test.sh`: Verifier entrypoint; it runs [tests/grade.py](./harbor/task-template/tests/grade.py) with `litellm`.
