# MILU

[MILU](https://github.com/AI4Bharat/MILU) evaluates multiple-choice knowledge across
11 languages. This integration uses answer-letter likelihood scoring and Gym's
existing `mcqa` verifier. It is experimental (`verified: false`).

## Protocol

- Dataset: `ai4bharat/MILU`, revision `846d7016558b2004386f30e59a2158731262492f`
  (CC-BY-4.0), `test` split: 79,608 questions across English, Bengali, Hindi,
  Tamil, Telugu, Malayalam, Kannada, Marathi, Gujarati, Punjabi, and Odia.
- Reference implementation: AI4Bharat/MILU at
  `7d8e6c9102bf44ae9f9ee84cfabefb4cb8fa2e88`; its MIT license is retained here.
- Default: five same-language validation examples sampled without replacement
  for each question using the harness's `default` random sampler behavior and
  seed 42. The seed resets per language. Equal-document examples are excluded
  without replenishment; preparing a subset preserves the full run's samples.
- Prompts begin with the question trimmed using `.strip()`, followed by labeled
  options and `Answer:`, separated by literal `\n` characters, matching
  the reference YAML escaping. Demonstrations end with the correct answer letter;
  two actual newlines separate demonstrations, as in the reference harness.
- The scored continuations are ` A`, ` B`, ` C`, and ` D`. Sum only continuation
  token log probabilities and select the largest sum; ties select the first
  letter. There is no length normalization, answer generation, or judge.
- Raw prompts are the default (`render_chat_template=false`). When enabled,
  the model's tokenizer renders the demonstrations and question as one user
  message with `apply_chat_template(tokenize=False, add_generation_prompt=True)`.

Random sampling and letter scoring differ from upstream MILU's first-N,
full-option protocol, so scores should be labeled with these settings.

The `multiple_choice` agent passes the selected option's letter to `mcqa` in its
existing boxed-answer format. That letter is constructed from likelihoods, not
generated by the model. `vllm_loglikelihood` extends Gym's vLLM transport with
`/loglikelihood`; these are the only new server implementations.

## Usage

Run from an installed Gym checkout with Hugging Face access to the dataset.
The example selects Hindi; omit `prepare_script_args` for all 11 languages.

```bash
gym eval prepare --benchmark indic/milu \
  '+prepare_script_args={languages:[hi],num_fewshot:5,fewshot_seed:42}' \
  +use_cached_prepared_benchmarks=false

gym eval run --benchmark indic/milu --model-type vllm_loglikelihood \
  --model YOUR_MODEL --model-url http://HOST:PORT/v1 --model-api-key dummy \
  --split benchmark --concurrency 8 --output results/milu/rollouts.jsonl
```

Re-prepare previously generated data with the cache disabled as above. Set
`fewshot_seed` to change the sampled examples. Direct preparation also accepts
`--num-fewshot` and `--fewshot-seed`.

Select chat formatting by appending either option to `gym eval run`:

```bash
+policy_model.responses_api_models.vllm_loglikelihood.render_chat_template=true
```

```bash
+policy_model.responses_api_models.vllm_loglikelihood.render_chat_template=false
```

`true` applies the tokenizer's chat template; `false` (the default) scores the raw prompt.
Both use the same five-shot data and letter continuations. In chat mode, the
model server loads the tokenizer from `--model`; if the served name is an alias, pass
`+policy_model.responses_api_models.vllm_loglikelihood.tokenizer=TOKENIZER_PATH_OR_ID`.
Use the same tokenizer revision as the inference endpoint.

The endpoint needs `/tokenize` and echoed `/v1/completions` log probabilities.
For Gemma, add
`+policy_model.responses_api_models.vllm_loglikelihood.likelihood_add_special_tokens=true`
to match the reference tokenizer settings; the default is false. Each question
uses four completion requests, each with one discarded generated token. The
adapter rejects missing/nonfinite scores, ambiguous token boundaries, and context
overflow (default limit: 16,384 tokens). Generation sampling overrides do not
control the likelihood score.

Use `question_ids:["0","1","2","3","4"]` for a smoke subset or `num_fewshot:0`
for zero-shot evaluation. Prepared rows retain language, subject, domain,
translation status, source revision, sampling seed, and selected demonstration IDs.
`data/example.jsonl` contains five synthetic format examples.

## Results and tests

### Reproducibility baseline

The following full-test results use the reference lm-evaluation-harness configuration
matched by this integration: five shots, seed 42, raw prompts
(`render_chat_template=false`), letter likelihoods, maximum length 16,384, and
question-weighted `acc,none`. The harness revision is
`d1cadb4bc51ab3afa113183ee600419503414ed3`; every row covers all 79,608 questions.

| Model | Model revision | Correct | Accuracy (%) |
| --- | --- | ---: | ---: |
| `google/gemma-4-26B-A4B` | `24548b62aa021d562695c04aaf7758a1ea47990b` | 53,055 / 79,608 | 66.6453 |
| `google/gemma-4-31B` | `5bbc2fb1c1b2c611d06e3d9f23c170ba21659d89` | 60,187 / 79,608 | 75.6042 |
| `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-Base-BF16` | `e0ac9ee3dfd02be21b5479edfc2f671ed269d0a2` | 41,389 / 79,608 | 51.9910 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-Base-BF16` | `b4cc202094ea3644bc4461c9fe58ec8b6a3695eb` | 58,307 / 79,608 | 73.2426 |

Use the standard MCQA `pass@1/accuracy` metric (0–100%) with one attempt per
question; `mean/reward` remains on a 0–1 scale. Across languages this is
question-weighted. Inspect Gym's coverage and failure
outputs before reporting a score; partial runs are not full benchmark results.
For language scores, prepare and run each language separately. Keep the selected
languages, shot count, model/tokenizer revisions, and resolved config with results.

Generic generation-health checks can report likelihood-only
runs as `unobserved`; inspect the saved `likelihood` token scores and coverage.

```bash
pytest --import-mode=importlib benchmarks/indic/milu/tests \
  responses_api_agents/multiple_choice/tests responses_api_models/vllm_loglikelihood/tests
gym env test --resources-server mcqa
```
