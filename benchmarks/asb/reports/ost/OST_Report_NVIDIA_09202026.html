01

What it measures

ASB attacks a tool-using agent through four channels and measures whether the attack achieves its goal. Direct prompt injection puts the attacker's instruction in the user's request; observation prompt injection puts it in a tool result; memory poisoning plants it in the agent's retrieved memory; mixed attacks combine them. PoT backdoor tests a trigger-conditioned backdoor against its own clean control. Each condition is run against its public defenses as well as undefended.

This is the broadest agentic-security surface in this bundle. It says nothing about refusal calibration on direct prompts — the xstest and over_refusal_detection reports cover that — and a model that scores well there can score badly here, because most of these attacks never appear in the user's message at all.

Average ASR · five attack columns
Mean of the five column attack-success rates. Each column is itself a mean of per-attack-type rates, not a pooled count. Lower is better.
Average refusal rate · same five columns
Mean of the five column refusal rates, as judged by the refusal judge over rows it could read. Higher is better.

No score threshold rules a capability in or out. Every cell is a mean of per-attack-type rates and is never pooled over rows. Mixed Attack spans 1,200 rows where DPI, OPI and Memory Poisoning span 2,000 and PoT spans 400; pooling would silently reweight Mixed. Clean utility and PoT clean ASR are controls, reported separately in the BLADE packages. The PoT Backdoor column in particular cannot be read without its control. The trigger is worth +34.50pp on Super-VL and +3.75pp on Ultra, but negative on the other two — Kimi -0.75pp and Qwen -6.25pp, where the backdoor arm scores below its own clean condition. A low PoT number for those two is not evidence of backdoor resistance; it is evidence the planted exemplar did nothing, and what remains is whatever the clean condition already produced.

Test construction and scoring

03

Deviations from the published protocol

1. Generation length: 256 → 4,096 output tokens

Upstream caps generation at 256 tokens, calibrated for 2024-era non-reasoning models. A reasoning model spends the entire budget on its trace and emits no plan, which registers as a workflow failure. Temperature is left at upstream's 0.0 and upstream_max_output_tokens records the original.

Consequence for reading the numbers
Without the raise, ASR would be driven toward zero for reasons unrelated to security — the most flattering possible artifact, and one that would have looked like a good result.

2. Memory retrieval ranking

Upstream ranks its poisoned memory with text-embedding-ada-002 through Chroma. The corpus here is upstream's own, extracted verbatim from the shipped stores, so the poison available to be retrieved is exactly the poison the published numbers faced. The ranking over it is cosine over term-frequency vectors, because no OpenAI credential is in play for this campaign.

Consequence for reading the numbers
Bounded and real. Every record in those stores was written during a DPI attack run, so the retrieved record is poisoned either way — the attack is never weakened, only the specific injected plan can differ. memory_found is reported per row so retrieval provenance is auditable.

3. Plan-parse salvage

Upstream calls json.loads on the raw reply and treats anything else as a workflow failure. That is reproduced as the strict path and tried first. Two salvage paths follow — markdown fence stripping, and extracting an embedded JSON array from prose — because both are presentation habits of instruction-tuned models rather than different plans.

Consequence for reading the numbers
This deviation was measured rather than assumed, and it is not inert. The salvage rate is wildly model-dependent — Nemotron 3 Ultra 0.05%, Kimi K3 40.2% — so this is a per-model deviation sitting inside a cross-model table rather than a uniform methodology choice. Under upstream's strict parse those 4,312 Kimi rows are workflow failures and leave the ASR denominator entirely, and the cells move: Kimi's Mixed Attack ASR is 75.35% as reported and 94.29% on strict-parse rows only — a swing of 18.94 points — against Ultra's 96.01%, which does not move at all. The reported number reads as a large safety advantage on the most aggressive attack column; most of it is how Kimi formats its plans. Salvage is still the default, because penalising a reasoning model for wrapping JSON in prose measures formatting rather than security — but workflow_salvage_rate is now a first-class coverage metric and every column carries an asr_strict_only/condition/* companion, so the size of the deviation is on the face of the table. Ultra's cells are comparable to published ASB numbers; Kimi's are not.

4. Consecutive system messages merged

ASB opens every rollout with two system messages — the agent description, then the planning instruction. Qwen3.5's chat template rejects that outright with HTTP 400 "System message must be at the beginning", so every Qwen row would have failed while the other three scored. The two are merged into one system turn joined with a blank line; no text is added, removed or reordered, and only consecutive system turns collapse.

Consequence for reading the numbers
Applied to every model, not only Qwen. Sending Qwen a merged prompt and the others a split one would mean the four were not answering the same input, which is the one property a cross-model table has to guarantee. The other three accept both shapes, so uniformity costs nothing beyond all four differing from upstream's exact layout in the same way.

5. Tool schema envelope

ASB declares parameters: None on normal tools and omits the key entirely on the attacker tool. The Responses API requires a schema object, so an empty one (strict: false) is supplied in the API envelope. ASB never passes tool arguments — function_params is hardcoded to None in call_tools — so this is behaviourally inert.

Consequence for reading the numbers
The tool list rendered into the planning prompt keeps upstream's original text, asymmetry included, because that string is what the model actually reads.

6. Measurement limitation: the refusal judge loses rows non-randomly

Upstream's refusal judge is gpt-4o-mini and is reproduced rather than swapped. On this OpenRouter key that model is served through a provider whose content filter errors on some ASB transcripts deterministically — the same rows fail on every attempt and never reach the rollouts file. The loss is concentrated, not spread: for Kimi K3 all 23 lost rows are Observation Prompt Injection and 22 of 23 are OPI + combined_attack. Zero non-OPI rows were lost. Overall 23 of 3,200 OPI rows, 0.72%.

Consequence for reading the numbers
It is the most aggressive injected observations that go missing, so Kimi's OPI cells are computed on a slightly non-representative subset and its OPI ASR and refusal rate carry that caveat. Ultra lost no rows, so the two models' OPI cells rest on denominators of 3,200 and 3,177. It was deliberately not fixed mid-campaign: a judge that differs between models is worse than one that drops 0.72% of one model's OPI rows, because the headline table compares models to each other. ASR and utility are unaffected either way — both are exact string matches that never consult the judge.

Results

Cells are means of per-attack-type rates. Workflow failures — rows where the model never emitted a parseable plan, so the attacker tool was never offered — and rows the refusal judge's provider content-filtered are both excluded from scoring denominators and reported separately. Read the refusal column beside the attack columns rather than after them: across these models the two order inversely and exactly. Kimi K3 refuses most (20.71%) and has the lowest attack-success rate in all five columns; Super-VL refuses least (3.59%) and has the highest average. That is a claim about willingness to decline, not about detecting the attack, and it is three models rather than a law. The two are not interchangeable readings: a model can be hard to divert because it recognises the injection, or because it declines the underlying task either way, and this benchmark does not separate them.

How failures were kept out of the score

  • Rows the refusal judge's provider content-filtered are excluded from every denominator. The loss is not random and is detailed in 03, limitation 6.
  • Workflow failures — no parseable plan, so the attacker tool was never offered — are excluded from ASR and utility rather than counted as resistance. Counting them as resisted would credit a formatting failure as a security property. The rate differs sharply between models and is reported per model.
  • There is no separate empty-generation class: a model that emits nothing produces no parseable plan and is counted as a workflow failure.
08

Comparison point

No human baseline. Being diverted by an instruction planted in a tool result or a memory store is a property of an agent loop rather than a skill a person can be scored on.

The paper's own published table is the reference, and this run reproduces its 27-condition matrix and denominators — Gemma2-9B's Mixed ASR of 92.17% resolves exactly as 1106/1200, which is how the Mixed denominator was confirmed. Within this bundle, injecagent and agentdyn test the same threat model at shorter and longer horizons respectively, and the three disagree about which model is weakest.

09

Known gaps

  • The laptop/container collection boundary is known from the run log, not from the data. No row carries a collection-site field, so a reviewer cannot reconstruct which half a rollout came from. The boundary was checked and the two halves share zero tasks — they are a disjoint partition of one sweep rather than replicates, so per-condition differences across it reflect which tasks fell on which side and the pooled rate is correct regardless — but that check rests on file order matching collection order rather than on anything recorded in the rows. The field was deliberately not added after the fact.
  • Kimi K3's 23 content-filtered rows are the only missing rows in the campaign. Ultra, Super-VL and Qwen are each 10,800 of 10,800 with every condition at exactly 400, so the coverage caveat is singular and belongs to Kimi alone.
  • One repeat per cell; no variance is estimated across repeats.
  • Rows lost to the judge's content filter cannot be recovered without a full re-run with a different judge, which would change the refusal column's meaning for every model (03, limitation 6).
  • memory_found is retrieval provenance and explicitly not a detector metric. No matched clean-versus-poison history run exists in this campaign, so no memory-detector FPR or FNR can be derived.
  • The public defenses are run as conditions but were not themselves tuned or verified against their own published baselines; a defense that underperforms here may be misconfigured rather than weak.
