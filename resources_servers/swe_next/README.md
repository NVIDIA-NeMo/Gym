# SWE-Next resources server

Verification for [TIGER-Lab/SWE-Next](https://huggingface.co/datasets/TIGER-Lab/SWE-Next): Python
software-engineering tasks generated by the R2E ("Repo-to-Environment") pipeline.

Every row ships its own prebuilt image (`docker_image`), a workdir fixed at `/testbed`, and the same
test command across the whole dataset, so there is no per-row test-command construction.

Sandboxes come from `nemo_gym.sandbox`, so the same server runs on OpenSandbox or any other
configured provider.

## Grading

Verification applies the candidate patch and the held-out `test_patch`, runs the fixed R2E test
command, and grades against `expected_output_json` (a whole-suite PASSED/FAILED/ERROR snapshot from
the golden-patched instance), matching upstream's `DockerRuntime._calculate_reward_r2e`. This is not
a FAIL_TO_PASS/PASS_TO_PASS check; see `verification.py` for why.

## Prepare the data

`prepare_swe_next.py` only writes rows on `data/supported_instance_ids.txt` (1,998 instances whose
golden patch resolved in all three passes of a full-set golden-patch sweep).

```bash
SWE_NEXT_LIMIT=200 python -m resources_servers.swe_next.prepare_swe_next
```

## Golden-patch validation

Grades each task with the dataset's own patch, which measures the dataset rather than a model.

```bash
gym env start \
  --config resources_servers/swe_next/configs/swe_next.yaml \
  --config nemo_gym/sandbox/providers/opensandbox/configs/opensandbox.yaml

python resources_servers/swe_next/apply_golden_patch.py \
  +training_jsonl=resources_servers/swe_next/data/swe_next_training.jsonl \
  +output_jsonl=results/swe_next_golden_patch.jsonl \
  +concurrency=32 +limit=100
```

`aggregate_golden_patch.py` joins repeated passes into supported / flaky / broken / inconclusive
buckets, and `diagnose_failures.py` separates infra faults from row failures.

## Running an agent

`configs/swe_next_opencode.yaml` wires the opencode sandboxed agent to `swe_next_resources_server`,
pointed at `data/swe_next_training.jsonl`.

```bash
gym env start \
  --config resources_servers/swe_next/configs/swe_next_opencode.yaml \
  --config responses_api_models/vllm_model/configs/vllm_model.yaml
```
